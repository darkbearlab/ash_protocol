# 局內升級強化（3.45.0）

本規格只處理任務內升級；主選單 UPGRADES 的職業／技能解鎖仍擱置。舊 3.35.3 參數盤點保存在 [archive/perks-to-3.44.md](archive/perks-to-3.44.md)，其中友軍與抽選資料已過時。

## 抽選與選擇

使用任務 seed、獨立 perkPicks（已完成挑選次數）與固定鹽值產生局部 PRNG，不消耗戰鬥 RNG。每次從合格池抽最多三個不同 ID，打亂顯示順序；不再限定八組。相同種子與相同選擇路徑可重現，包含每日任務。不同回合的組合允許隨機重複，不強制排除上一組。

一個名額有 60% 機率優先從「已取得、未滿階、非一次性資源」抽取；其餘從剩餘合格池均勻抽。沒有符合的舊項目就正常抽。這不是整組含舊項目的最終機率：一般名額也可能抽到舊項目。戰地補給不享有已選加權。

當前 perkDraft={index,ids} 保存在單局，序列化時補齊未建立的待選組，重載保持原選項。每選一次 perkPicks +1、pendingPerks −1，生成下一組；多級連升逐次獨立抽選。choosePerk 必須處於 playing、有待選次數、ID 是當次選項且仍合格；非法選擇不套用效果。升級不花世界回合／戰鬥 RNG，也不倒數技能。

滿階項目離池；不足三個就顯示實際數量。所有永久項目全滿仍有無限次戰地補給，不強制湊三張重複卡。補給即使滿載仍可出現：醫療包照常增加，超量彈藥依既有規則落地。

命中仍走共用 10–99% 邊界。格鬥不需要先持近戰武器才出現，也不把目前裝備當作強制選項過濾。友軍不自動繼承玩家強化。

新武器增幅放在 perkWeaponBonus，依武器 burst 分攤（向上取整；目前連發為 2／3，均可整除 6），舊 bonus 的每發效果保持。部分彈匣／未命中／中途死亡不保證取得完整收益；下錨兩次攻擊各自享有，不改下錨時序。改裝加成仍照舊。

## 存檔 v28

新增 player.perks（各 ID 次數）、player.perkWeaponBonus、game.perkPicks、game.perkDraft。未知 ID、負值／非整數、重複或非法 draft、錯誤 index、缺必要欄位拒絕匯入。完整備份走 Game.restore，外層 v1／profile v4 不變。null draft 可在待選時依固定種子補齊，不造成重擲。

v1–27 保留全部原能力／HP／物資／RNG。以歷史 HP 基準 100／重裝 200、裝甲 0／重裝 6 和舊步進推算 damage／health／armor／blast／scavenger／medic／hazmat 次數；只有非負整數、整除且不超已選次數才列入。若推算總數超出已選次數，視為不明修改值，不臆造取得紀錄。已選次數用 max(0, level−1−pendingPerks)。補給歷史不可推回，記 0；新武器增幅初值 0，不重播舊獎勵。推回超過三階的舊紀錄仍保留，但不再提供該項目；不能因新上限削弱舊局。

這是保守推算，非完整歷史還原；異常／手改數值可能無法辨認。首讀既有 storage 管線先備份原 v27（或對應舊版本）字串，再儲存新版。

## 後續內容擴充／Claude 接手

PERKS 仍在 data.js，ID 固定不能重用。定義包含 cap（null＝一次性資源）、effect、數值；可選 characters（角色 ID 陣列）及 eligible(game) 條件。抽選、驗證和已選加權共用 eligiblePerks，不另寫一套 UI 條件。新通用數值可調 amount 等；文案目前在同一內容表，改值同步改文字。

效果處理集中 src/perks.js 的 applyPerk：現有數值型可沿用 effect；職業技能強化／取得新技能需新增效果處理與必要資料驗證，而不重寫抽選。每職業至少三項另與使用者討論，本輪未填入、不啟用主選單購買。不要把回合成本或技能觸發方式當一般數值改動。

測試見 tests/perks.test.mjs；四份人工場景由 node qa/create-3.45-fixtures.mjs 產生。新版階數卡與手機版面、自然戰力／加權手感留外部驗收。
