# 牆體幾何：cutaway 的代價與斜角俯視的重設計

- 日期：2026-09-10
- 提出者：Claude（Opus 5），受使用者委託
- 受測版本：**3.21.0**，commit `adb3c4c`
- **未修改任何程式或美術檔案。** 幾何實驗全部在瀏覽器 session 內即時套用，事後已還原。
- 本文是 `2026-09-10-claude-map-readability.md` 的延伸：那一篇談明度，這一篇談幾何。

## 先更正一個描述

使用者轉述的折衷法是「遮住的部分不顯示牆，只顯示上面的頂板」。
`src/walls.js` 實際上是**相反**的：

```js
capTop = center.y - tile/2 - tile*WALL_HEIGHT   // 頂板畫在牆自己那格的北邊一格
groundTop = center.y - tile/2                    // 牆面畫在牆自己那格
cutaway: g.grid[y-1]?.[x]===1 && Boolean(g.seen[y-1]?.[x])
...
ctx.save(); if(q.cutaway) ctx.globalAlpha *= .12;
texture(8+style.cap, q.capTop, q.height, '#52615b');
```

淡化的是**頂板**（`globalAlpha *= .12`），保留的是**牆面**。

這個方向其實是對的。頂板正是壓在鄰格上的那一塊，牆面才落在牆自己那一格；
先犧牲頂板，代表「牆的標記留在正確的格子上」。問題不在選錯了要藏哪一塊，
**問題在於它是有條件的**。

## 量化：同一件事有三種長相

在瀏覽器中攔截 `drawImage`，以 `(dx, groundTop)` 為鍵，統計單一畫面內每一根牆柱
實際畫出了什麼。視野內 27 根牆柱：

| 呈現 | 數量 | 條件 |
| --- | ---: | --- |
| 完整立塊（頂板＋牆面） | 12 | `!cutaway && front` |
| 只剩牆面（頂板 12%） | 11 | `cutaway && front` |
| **幾乎不可見**（無牆面，頂板 12%） | **4** | `cutaway && !front` |

全畫面的頂板繪製中，**55.6% 是以 12% alpha 畫出的**。

也就是說「這一格是牆」這個單一事實，在畫面上有三種完全不同的外觀，
而且外觀取決於鄰格的狀態。玩家的眼睛學不到穩定的規則——這就是資訊雜亂的來源，
跟明度無關，是幾何造成的。

## 其中 4 根是真的 bug，不只是雜訊

`front = !neighbors[2]`（南邊是牆就不畫牆面）與 `cutaway`（北邊是已知地板就淡化頂板）
可以同時成立。條件很常見：**任何厚度 ≥2 格、北側是走道的牆帶，其最北那一排**。

這種格子畫出來是「12% 的頂板 ＋ 完全沒有牆面」，實際看起來就是一格空地板。
我在瀏覽器裡把符合此條件的格子描紅框確認過，它們確實落在看起來可走的區域上。
單一畫面 4/27 ≈ **15% 的可見牆柱長得像地板**。

這一條本身就足以構成修改理由，與美術風格取捨無關。

## 建議的重設計：降低視角高度，而不是縮小牆

使用者提出的方向是對的，而且是幾何上正確的那一個：**牆面上下壓縮、頂面保持完整**。

斜角俯視（oblique projection）中，一個高度 `k`、位於邊長 `T` 的格子上的方塊：

- **頂面**＝一個完整的 `T x T` 正方形，整體上移 `k`
- **南側面**＝緊接在頂面下方、高度 `k` 的一條帶
- 螢幕總佔用＝`T + k`

現行程式相當於 `k = T`（升高整整一格），所以佔用 2 格。
把 `k` 調小而頂面維持 `T x T`，等同於**把鏡頭抬高一點**，不是把牆變矮——
透視仍然自洽，只是俯角變大。

這個版本比「頂面也一起壓縮」好，關鍵原因是：**頂板貼圖完全不必重畫**，
維持 32x32 原樣，只是繪製位置上移 `k`。

以 `T = 32` 計：

| `k` | 螢幕佔用 | 遮住北格的比例 | 備註 |
| --- | ---: | ---: | --- |
| `0.30T` ≈ 10px | 42px | 30% | 最保守 |
| **`0.40T` ≈ 13px** | **45px** | **40%** | 建議起點 |
| `1.00T` = 32px | 64px | 100% | 現行 |

遮擋從「100% 但有條件」變成「40% 且無條件」。
**`cutaway` 與其相關分支可以整段刪除**，所有牆長得一模一樣。
被遮住的是北格的下緣 40%，那一段本來就是最靠近牆的部分，語意上也說得通。

## 需要重畫的只有牆面

把 32px 的牆面壓成 13px 是我實測過的作法，結果是材質細節糊成一團。
八張 face 的辨識度本來就低（我量過其中六張的亮度全部擠在 29.9–39.6），壓縮後等於全部一樣。

兩個作法，都比直接壓縮好：

1. **重畫成 32x13 的專用貼圖。** 13px 高養不起垂直細節，但橫向細節活得下來。
   每張只保留**一條水平特徵**——一道管線、一排通風槽、一列螺栓——
   加上最底部 1px 的暗線當作與地板的接縫。
2. **或乾脆放棄材質分辨。** 如果八種材質只是裝飾而非資訊，收斂成 2–3 種，
   把像素預算花在明暗分界上。

我也試過「裁切」而非「壓縮」（只取來源貼圖上緣 13px），像素比較銳利，
但語意上不如重畫；列在這裡供比較。

## 三個讓「立體感」真正成立的細節

高度感其實不是靠位移撐起來的，這三項的效益比多給幾個像素的高度大得多：

- **落地投影。** 牆南側地板畫一條高 `0.35T` 的漸層黑（`rgba(0,0,0,0.5)` → 透明）。
  眼睛是用陰影長度判斷高度的；有投影的矮牆看起來比沒投影的高牆還高。
- **頂緣高光。** 頂板上緣 1px 亮線（約 `rgba(200,214,208,0.32)`）。成本為零。
- **拉大頂／面的明暗差。** 現況頂板 50.5、牆面 38.0，只差 12.5。
  建議拉到 25 以上，讓牆面明確是背光側。光源方向必須全圖一致。

另外一項與幾何無關、但效益最高的：**為每一塊連續牆區描 1px 輪廓線**。
把「不可走」定義成一個封閉形狀，而不是一種材質，這在格狀遊戲裡是最便宜的可讀性改善。

## 出貨前要確認的一件事

繪製順序。若單位與物件是在所有地形之後才畫，站在牆北邊那格的單位會蓋過牆的頂板，
立體感會破（但可讀性不受損）；若是逐列交錯繪製，牆會正確地遮住單位的腳。
兩種都能接受，但應該是刻意選的，不要是碰巧的結果。
`k = 0.40` 時重疊只有 13px，影響比現在小很多。
