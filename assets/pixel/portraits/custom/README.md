# 外部頭像交付規格 v1

本目錄供使用者或其他應用交付 ASH PROTOCOL 的自訂頭像。

**目前狀態：規格已建立；自動掃描、素材驗證、加入隨機池與自訂頭像缺檔回退尚未實作。** 把圖片放進此目錄，現在的 3.18.0 不會自動選到它。素材可以先製作，待管線接好後再建置／發布。

## 放置位置

```text
C:\codex_projects\shooter_roguelike\assets\pixel\portraits\custom\
  my-operator.png
  my-operator.json    # 可省略，作者與來源資訊
```

直接放在本目錄，不使用子目錄。每張頭像獨立一個 PNG；若用圖集生成，須先切成單張成品。來源圖、提示與加工暫存檔放專案的 `art/portraits-custom/`，不要混進本目錄。

## 必須符合的檔案規格

| 項目 | 規格 |
| --- | --- |
| 格式 | PNG，單張靜態圖片，不接受 APNG、JPEG、WebP 或 SVG |
| 尺寸 | **64 × 64 像素**，不是放大後的 128／256／1024 像素圖 |
| 顏色 | 可見像素最多 **32 種 RGBA 色值**，建議控制在 16 色；完全透明的像素不計色數 |
| 色彩模式 | 索引色 PNG 或 RGB／RGBA PNG 均可，建議使用標準 sRGB |
| 透明度 | 可不透明或使用透明背景；alpha 只用 0／255，不用半透明邊緣 |
| 檔名 | 不含副檔名部分符合 `^[a-z0-9][a-z0-9_-]{0,47}$`，副檔名固定小寫 `.png` |
| 唯一性 | 本目錄內檔名唯一；已發布的檔名是身分識別，之後不可改名或借給另一人物 |
| 圖內元素 | 不含名字、文字標籤、UI 邊框、KIA 印章或死亡效果 |

收件端不應默默裁切、縮放或重新量化成品；不符合尺寸／色數時應指出檔名與原因，讓製作者修正，避免改壞已完成的像素細節。RGB555 可作製作時的建議色盤，**不是 v1 的強制收件條件**。

## 構圖與畫風

- 日系科幻角色，正面或微側正面、視線朝向觀者，頭部與少量肩部入鏡。外觀不綁定 Soldier／Recon／Bulwark 的能力或職業。
- 頭臉置中，頭頂與左右保留約 3–4 像素空間，避免頭髮或臉被裁斷。下方約 10 像素以肩部／衣領為主，讓遊戲疊 KIA 時仍看得出人物。
- 真正為 64×64 設計的像素群、清楚輪廓、節制陰影；不要用高解析精細畫作直接硬縮出大量雜點。
- 不使用平滑插值、抗鋸齒、模糊或連續漸層；預覽請以最近鄰放大。檢查原尺寸下五官是否仍可辨識。
- 背景建議低對比、低飽和，讓臉與頭髮清楚。透明背景也可；不用自行畫遊戲介面框。
- 可參考上一層目錄的 `ember.png`、`onyx.png`、`silver.png`、`cedar.png` 與 `portrait-05.png` 至 `portrait-16.png`。只參考，不覆寫內建成品。

## 可選的同名 JSON

`my-operator.json` 使用 UTF-8、有效 JSON，可提供：

```json
{
  "name": "角色外觀名稱",
  "author": "製作者",
  "source": "原創／使用工具或素材來源說明"
}
```

三個欄位皆可省略；若有則為字串。它們只作素材資料，不替換玩家職業名稱，不改技能／數值，也不指定抽選權重。ID 由 PNG 檔名產生，不在 JSON 中自訂。未提供 JSON 仍是完整交付。

## 預定接入行為（尚未實作）

1. `npm start` 與 `npm run build` 掃描此目錄，驗證圖片／同名 metadata，產生自動清單；製作者不需改 JavaScript 或 Service Worker。
2. 自訂身分格式預定為 `custom:<檔名主體>`，例如 `custom:my-operator`；與內建 ID 分開。
3. 合格素材與內建頭像合併，等機率抽選，同一次選角避免重複。不消耗地圖／戰鬥 RNG；確認部署後隨本局固定。
4. 背包、繼續任務、成功／失敗畫面沿用同張；遊戲自己疊死亡降彩度與 KIA，勿另交「死亡版」。
5. 自訂 ID 的圖片日後缺失時，保留 ID 並顯示內建替代圖，不能讓任務／完整備份載入失敗；圖片恢復後可重新顯示原外觀。
6. 圖片納入發布與離線快取。線上遊戲要重新建置並發布才會取得新增圖片，不會直接讀取使用者電腦上的資料夾。

## 外部應用交付範圍

交付本目錄的 PNG 與可選 JSON 即可；保留本 README，不修改遊戲程式、內建頭像或正式存檔。製作報告可列出檔名、尺寸、可見色數與來源。素材處理管線、收件驗證與遊戲接入由後續開發負責。
