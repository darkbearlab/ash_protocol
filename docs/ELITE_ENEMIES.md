# 小菁英（規格，2026-09-14）

- 狀態：**3.79.0 規則已實作。** 介面由 Claude 接手（第 3 節）。
- **順序：排在 [FACTION_DATA.md](FACTION_DATA.md) 之後。** 派系框架要先以「規則不變」通過行為一致性檢查；小菁英會刻意改變生成結果，必須是下一個獨立提交。
- 目的：深層出現少數帶很多隱藏詞條的敵人，玩家只能靠染色認出「這隻不一樣」。

## 1. 使用者決定（2026-09-14）

1. 小菁英**只多加詞條、多給經驗**。廢料、掉落、協定點數等其他資源，暫時不額外給。
2. **出現頻率跟著深度走。**
3. **只靠染色辨認。** 可以在目標卡加一個沒有效果的「精英」標籤；如果日後這個標籤要帶規則（例如獎勵掉落），再把規則接上去。
4. 敵人圖要能染色，主要就是給小菁英用。通用染色能力已規劃在 FACTION_DATA.md 第 9 節。

## 2. 規則（Codex）

### 2.1 誰可以成為小菁英

**使用者已確認（2026-09-14）**：排除雜兵（`expendable`）與頭目級（`boss` 標籤）。

- 雜兵本來就不抽詞條。
- 頭目本身已經是特例，再變成小菁英容易失控。

若使用者之後要讓頭目也能成為小菁英，只要拿掉這個排除條件。

### 2.2 判定時機

凡是會抽詞條的出生路徑都一起判定，目前有兩處：

- 地圖生成（world.js 的 `generate`）。
- `Game.spawnEnemy` 的執行期出生：蟲巢產物、增援、撤退增援。

### 2.3 機率

`eliteChance(floor, offset)` 用含難度偏移的有效深度計算，和 `affixChance` 一樣。

初始建議值，放在 `ELITE_TUNING`，都可以再調：

| 欄位 | 建議值 | 說明 |
| --- | --- | --- |
| `startDepth` | 9 | 有效深度 9 起才可能出現。詞條第 7 層起出現，讓玩家先熟悉詞條 |
| `chancePerDepth` | 0.02 | 每深一層增加 2% |
| `chanceCap` | 0.15 | 最多 15%（有效深度 16 達到上限） |
| `minAffixes` | 3 | 保證的詞條下限 |
| `xpMultiplier` | 2 | 擊殺經驗倍率 |

標準難度的六層任務，有效深度最多到 6，不會出現小菁英。之後的難度旋鈕會讓它提早出現。

### 2.4 亂數

- 小菁英判定與補抽詞條，**使用獨立的出生亂數流**，例如 `birthRandom` 加上不同的鹽。
- **不得改變非小菁英敵人的詞條結果**，也不動地圖亂數。
- 所以行為一致性檢查的差異，只會出現在真的生出小菁英的深層樓層（第 4 節）。

### 2.5 詞條

- 先照現在的流程抽詞條。
- 不足下限時，從剩下「這個敵人可以套用」的詞條中均勻補抽，直到達到 `minAffixes`，或可套用的詞條用完為止。
  - 持槍兵種最多 5 個，其他兵種最多 3 個。已經有的被動（例如狙擊手本來就有夜視）不能再抽，所以實際可能更少。
- 詞條照樣隱藏、照樣靠發動顯現，名稱照樣只帶一個「？」。

### 2.6 經驗

- 擊殺經驗乘上 `xpMultiplier`，取整數。
- 其他資源不變。

### 2.7 敵人欄位與存檔

- 敵人新增 `elite: true`；非小菁英不寫這個欄位。
- 存檔版本接在 FACTION_DATA 的 40 之後，升為 41。
  - 遷移：舊存檔一律沒有小菁英。
  - 驗證：`elite` 只能是 `true` 或不存在。
- **召喚物**：死靈法師召喚小菁英的屍體時，友軍要不要保留 `elite`，由 Codex 決定並寫進報告。Claude 建議移除，友軍用不到。

### 2.8 與派系的關係

暫時不依派系調整機率。之後如果需要，可以在派系清單加一個機率權重欄位。

## 3. 介面（Claude）

  - 被動標籤那一行加一個顯示用的「精英」標籤。它沒有規則效果，也不是 `TRAITS` 裡的被動。

- **圖鑑**：不列小菁英。
- **喊話**：不變。

## 4. 驗收

### 4.1 自動測試

`npm test` 全數通過，並新增以下測試：

- 有效深度低於 `startDepth` 時機率為 0；之後隨深度增加，並在上限封頂。
- 小菁英的詞條數至少是 `min(minAffixes, 可套用數)`。
- **非小菁英的詞條結果與加入小菁英之前相同**：同種子、同敵人代號逐一比對。
- 頭目與雜兵不會成為小菁英（如果採用第 2.1 節的建議）。
- 擊殺經驗倍率正確，其他資源不變。
- 存檔往返後保留 `elite`；舊存檔遷移後沒有小菁英。

### 4.2 行為一致性檢查：刻意改變規則，需要重錄基準

重錄前要先證明「差異只出現在應該出現的地方」：

1. 先跑一次 `node qa/enemy-data-identity.mjs`，保留完整差異清單。
2. 差異只能出現在有效深度 ≥ `startDepth` 的地圖與局面。以檢查腳本的涵蓋範圍來說：
   - 現行生成器：第 9–12 層。
   - 難度偏移 6：第 3–6 層。
   - 任務局面：無盡模式第 12 層。
3. 以下必須仍然完全一致：
   - 偏移 0 的第 1–8 層地圖、舊版生成器全部。
   - 其他任務局面。
   - 機器人重跑（一般任務最深只到第 6 層）。
4. 確認之後才用 `--write` 重錄基準，並在報告中附上差異清單。

Claude 在介面批次中，用瀏覽器確認染色與「精英」標籤。

## 6. 實作現況（3.79.0）

- `src/elite-enemies.js` 集中 `ELITE_TUNING`，採第 2.3 節全部建議值。有效深度 9 起 2%，16 起封頂 15%。頭目標籤、實例或兵種資料的 expendable 都排除。
- `generate` 與 `Game.spawnEnemy` 在普通詞條之後呼叫 `rollEnemyElite(e, seed, floor, offset)`。`birthRandom` 新增可選 salt；原預設 `enemy-v10` 不變，精英用 `elite-v1`。補抽均勻、不讀派系權重，每次重新檢查適用條件；沒有多抽地圖／戰鬥亂數。
- 實例只增加可選 `elite:true`，非精英保持沒有欄位。詞條沿用 `affixes`／`traits`、隱藏與顯現規則，名稱不自行加精英片段。
- `enemyKillXp(e)` 僅將經驗乘 2 並四捨五入。廢料、掉落與協定獎勵不加成；撤退增援仍有原本經驗／廢料，沒有物資掉落。較多經驗間接提早升級或封頂補給，屬既有升級規則。
- save41：v40 與更舊存檔清除 elite，不回溯重抽；當層、封存敵人與友軍一併處理。當前格式只接受 true 或不存在。profile5／backup1 不變，完整備份走相同遷移與驗證。
- 召喚物維持既有「依屍體兵種建立新友軍」流程，不複製 elite 或屍體的詞條；敵人屍體保留 elite 可供染色。
- 實際含精英的生成結果加一層 `{version:11, recipeId:'elites-v11', base:原世代10描述}`，保留 1–10 讀取。沒有生成精英的樓層維持原描述，確保淺層及未改變的種子完全相同。執行期出生不改已生成地圖的描述。
- 原基準比對 154 筆差異均符合第 4.2 節；完整清單與結果見 [QA 報告](../qa/results/2026-09-14-codex-3.79.0-elites.md)。通過範圍檢查後才使用 `--write` 更新基準；未變動雜湊或擷取邏輯，檢查器只取消原先最多印 30 筆的限制。

## 8. Claude 介面接線（3.79.1，已完成）

- **外框**：`enemy.elite===true` 時，renderer 先把該圖集格做成金色剪影，往上下左右各偏移 1 像素畫出，再疊上原本的角色（可能已染色），所以派系塗裝仍看得出來。沒有圖時畫金色方框。
- **屍體**：`corpse()` 多接收敵人物件，小菁英的屍體同樣畫外框。
