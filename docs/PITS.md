# 坑洞（天井）

3.164.0，使用者決定 2026-09-23，Claude 實作。原本是「陽台地形」的構想——一格一格鏤空的地形與邊緣磚，例如一個巨大的天井，邊緣可能有半掩體，機制上是不擋視線的牆。當時擱置，這一版補上。

## 1. 規則

格子多了第三種值：`0` 牆、`1` 地板、`VOID`（`data.js`，值 2）坑洞。

| | 坑洞 |
| --- | --- |
| 走進去 | 不行。撞上去說「被擋住了」 |
| 視線、射擊 | 穿過（`world.js` 的 `lineOfSight`：`seeThrough` 讓坑洞和地板一樣透明，起點與終點也可以是坑洞） |
| 爆炸 | 越過坑洞照樣波及範圍內的單位 |
| 投擲物、照明彈、誘餌、地雷、盲射、壓制射擊的落點 | 不能落在坑洞（這些原本就只接受地板） |
| 逃命繩索、重部署鉤索、鉤鎖、鉤舌 | 可以橫越，落點仍然要是地板（使用者同意 Claude 的建議） |
| 會飛的敵人（無人機、浮游彈藥） | 可以懸在坑洞上（`passable` 只對 `flying` 放行）；在坑洞中央被擊落時，掉落物移到最近的地板 |
| 掩體 | 坑洞邊緣**不是牆**，站在邊上沒有牆壁掩護（`combat.js` 的 `adjacentWalls`） |
| 煙霧、毒霧 | 只停在地板上（存檔的雲團只記地板格）；震撼彈與 EMP 仍會影響懸在坑洞上的單位 |

## 2. 邊緣

- **警告線**：坑洞邊緣的地板上畫一圈紅黑相間的警告線（`renderer.js` 的 `pitRim`），沿著每一條通往坑洞的邊，外角也補上，所以整圈是封閉的。畫法仿隨機裝飾物：在地板之後、暗區陰影／迷霧／物件／欄杆之前，但**位置和大小固定**，不隨機。
- **欄杆**：每一側有一半機率整側加欄杆，就是現有的矮隔板（半掩體、不擋視線與射擊、可破壞）。欄杆畫在警告線上面，所以水平方向的上緣警告線可能被欄杆遮住；欄杆被打爛後警告線就露出來（使用者：「所以沒關係」）。
- 欄杆是翻不過去的——另一側是坑洞，本來就不能站。
- **坑洞本身**：不畫任何地磚（使用者暫定），看到的是背景。
- 樓層地圖上，看過的坑洞格畫成深色、紅框。

## 3. 生成

- 仿可插入的生活模組：在一個房間裡挖一個長方形坑洞，**2×2 到 5×5**，依房間大小——每邊是房間邊長減 3，限制在 2～5（一般房間 3×3～4×4，合併的大廳可到 5×5）；放不下就一次縮一邊，最小 2×2。
- **每層有一半機率**挖一個（`PIT_TUNING.chance`），最多一個。
- 不挖在起點房間、出口房間。坑洞四周一定留一圈地板走道（不碰房間的牆）。
- 不挖在任何生成時放下的東西上：單位、物品、物件與生活模組、槽位、通道與路徑、門與隔板的兩側、起點與出口（`pits.js` 的 `takenTiles` 直接把整張地圖當資料掃，新加的東西不會漏）。
- 挖完整層必須仍然全部連通（`generationSafe`），否則不挖。
- 順序：在戰鬥人口、補給、巢穴都放好之後，在研究員、蟲潮出口、終端分類與保險室之前；那些只會用地板，所以自然繞開坑洞。用自己的雜湊，所以**只有挖到坑洞的樓層會變**。

## 4. 存檔

- SAVE 70。舊存檔沒有坑洞，不需要遷移；新存檔的格子可能有 `VOID`。
- 驗證放寬：欄杆可以一邊是坑洞（至少一邊是地板）；封存樓層的格子接受 `VOID`；預警掃到懸在坑洞上的無人機，掃描點也接受坑洞。

## 5. 數據（第 1～6 層，種子 1～60，共 360 層）

- 184 層有坑洞（51%），全部連通。
- 尺寸：2×2 53、5×2 24、3×2 19、3×3 15、5×4 13、4×3 12、5×5 11、2×3 8、5×3 8、4×4 6、4×2 6、3×4 4、4×5 3、2×4 2。常常縮到 2×2，因為房間中央常有物件。
- 有坑洞的樓層平均 6.9 段欄杆。
