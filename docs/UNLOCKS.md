# 解鎖目錄：職業與故事片段（規格，2026-09-15）

- **狀態**：3.90.0 規則層已實作；介面由 Claude 接續。
- **分工**：
  - Codex：規則層。解鎖目錄資料、同一個取得入口、無盡的職業屍體、無盡每層重抽派系、故事片段的撤離確認、選角閘門、取消攜行升級、玩家檔案升版與退款。
  - Claude：介面，在 Codex 之後做。解鎖頁、部署與街機的鎖定顯示、提示文字、解鎖演出、故事內容與價格調整。
- **取代**：
  - [PROGRESSION.md](PROGRESSION.md) 的攜行升級，以及 3.33.0 的佔位卡片。
  - PROGRESSION.md「既有玩家不可倒退」那一條，使用者已改成直接鎖回（第 1 節第 8 項）。

## 1. 使用者決定（2026-09-15）

1. **只保留職業解鎖**：取消職業以外的所有永久解鎖與升級。每一局都從固定配給開始，這樣才真的是 roguelike。
2. **兩條管道，同一個鉤子**：解鎖可以用協定點數購買，也可以在地圖上遇到互動物件取得。兩條路走同一筆目錄項目、同一個取得入口。
3. **故事也能買**：故事片段也能用協定點數解開，不會因為抽不到就永遠看不到。
4. **起始職業**：一開始開放士兵、偵察兵、工程師，分別展示正面火力、道具和召喚物。
   - 工程師之後要重設計，所以試玩版暫時不凍結。
5. **職業屍體**：在無盡模式裡依公式逐層提高出現機率，從還沒解鎖的職業中隨機抽。一局可以回收好幾個，只要深入得下去。
6. **取得時機**：故事片段要成功撤離才解鎖；職業屍體互動當下就解鎖。
7. **價格**：職業與故事都是 **100 點**（3.156.0，使用者決定：先讓整份名單在幾局內就能湊齊）。
8. **舊玩家檔案直接鎖回**：起始三職業以外的職業重新鎖定。
9. **屍體公式**（3.151.0，使用者 2026-09-20 同意 Claude 建議的 1、3、4）：第 5 層起，每層出現機率 = min(50%, 10% × (層數 − 4))，一層最多一具；連續 4 層沒有時，下一層必定有。原本是第 8 層起 4% × (層數 − 7)，使用者一次都沒遇過。
10. **無盡模式每一層重抽一次派系**（依種子），而且只有職業屍體，沒有故事片段。
11. **屍體沒去互動就錯過**：抽到的職業這一局不會再出現。無盡模式是生存與探索的取捨。
12. **試玩版不開放其他職業**：只有起始三職業，不能購買，也沒有職業屍體。
13. **故事片段由使用者自己在本機維護**：用內容檔增刪修改，不需要透過 Claude 或 Codex（第 5.2 節）。

## 2. 解鎖目錄

- **形式**：一份靜態目錄，例如 `src/unlock-catalog.js`。每一筆包含：
  - `id`：穩定的識別字，存進玩家檔案。
  - `kind`：`character` 或 `story`。
  - `price`：協定點數。起始職業標記為起始解鎖，不賣。
  - `sources`：在地圖上的取得條件（第 4、5 節）。
  - 故事的標題與內容放在內容檔，由使用者維護（第 5.2 節）。
- **第一版項目**：
  - **職業 8 筆**：
    - 起始解鎖：soldier、recon、engineer。
    - 1000 點：necromancer、druid、bulwark、berserker、ninja，來源是無盡的職業屍體。
  - **故事片段 6 筆**，每筆 100 點：
    - 改由內容檔管理（第 5.2 節）。第一版就是現有的 `LORE` 6 段，來源沿用每層的資料物件（只在戰役任務出現）。
    - 之後由使用者依派系、深度擴充故事池（[STORY.md](STORY.md) 第 4 節）。
- **貨幣**：協定點數（`protocol.balance`）是唯一的貨幣，現有的發放規則不變。

## 3. 取得入口（同一個鉤子）

- **入口**：規則層提供一個取得入口，例如 `grantUnlock(profile, id, source)`。職業和故事、購買和撿到都走這裡。
- **已經解鎖**：沒有效果，回傳 false，也不扣點數。
- **購買**：驗證餘額；扣款和解鎖在同一次玩家檔案寫入完成（沿用 `purchaseCarrying` 的原子寫入做法）。
- **地圖取得**：
  - 職業屍體：互動當下就寫入玩家檔案，之後陣亡也保留。
  - 故事片段：撿到時記在這一局的待確認清單；成功撤離時在結算一併寫入；陣亡或放棄就丟失。
- **Kill house 模擬**：不產生也不取得任何解鎖。
- **每日種子與真實模式**：照常適用。

## 4. 職業屍體（無盡模式）

- **出現條件**：無盡模式、第 5 層以上（3.151.0 起；原為第 8 層），而且玩家檔案裡還有未解鎖的職業。
- **機率**：`min(50%, 10% × (層數 − 4))`，一層最多一具（`corpseChance`）。
- **保底**：連續 4 層沒抽到，下一層必定有（`corpseFloor`）。每層的抽籤都從種子算，保底由第 5 層往後重算，不需要存檔欄位。
  - 以抽籤計，不看遺體有沒有真的放下；沒有空位或職業都已解鎖時，那層算有抽到但沒有遺體。
  - 實測 5000 個種子：第 5～8 層各約 11%、20%、30%、39%，第 9 層 66%（含保底），之後約 50%；第 9 層以前一定遇過至少一次。
- **提示**（3.151.0）：
  - 進入樓層時，紀錄寫「偵測到失聯幹員的生命訊號：遺體上方有光柱，靠近後按互動回收識別資料。」，樓層提示也改成「生命訊號」；
  - 遺體上方有和鑰匙卡一樣的光柱，回收後消失。

  | 打到第幾層 | 預期遇到幾具 |
  | --- | --- |
  | 10 | 約 0.2 |
  | 12 | 約 0.6 |
  | 15 | 約 1.4 |
  | 20 | 約 3.6 |

- **決定的時機**：
  - 有沒有屍體、放在哪裡，只由種子與樓層決定。
  - 屍體是哪個職業，在載入樓層時依玩家檔案從未解鎖的職業中抽（用種子與樓層做亂數，不消耗戰鬥亂數），存進本局存檔。
  - 同一局已經出現過的職業，不論有沒有互動，都不會再出現（沒去互動就錯過）；全部解鎖時，這個位置不放屍體。
- **放置**：可以走到的非起始房間，互動後取得。
  - 外觀用該職業的倒地圖，看得出是哪個職業。
  - 是否佔格、能否當掩體，由 Codex 決定並寫明。
- **不變條件**：
  - 戰役與第 7 層以下的生成不變。
  - `qa/enemy-data-identity.mjs` 的無盡樣本可能因為每層重抽派系（第 5.1 節）與加入屍體而改變。Codex 要說明原因，只能影響無盡樣本，不可整批重錄基準。

## 5. 故事片段

- **第一版**：現有 6 段 `LORE`，沿用戰役任務每層的資料物件位置。
  - 撿到時照舊給協定點數與廢料。
  - 同時記進本局的待確認清單。
- **戰役**：成功撤離時寫入玩家檔案（原路回收在第 1 層撤離也算）。
- **無盡**：沒有故事片段。無盡樓層不放資料物件，所以也沒有資料的協定點數（使用者決定）。
- **閱讀**：已解鎖的片段在解鎖頁閱讀；未解鎖的顯示遮罩、價格與「可能在哪裡找到」。
- **之後的來源**：研究員或軍官身上攜帶的日誌。這很符合肅清的主題，但不在第一版。

## 5.1 無盡模式每層重抽派系（相關規則變更）

- **決定方式**：
  - 每一層的設施派系依「種子 + 樓層」決定，從可抽選的派系中挑（沿用 `rollFacilityFaction` 的派系池）。
  - 同一個種子，每一層的派系順序固定。
- **派系屬於樓層**：該層的敵人名單、頭目、喊話聲線、蟲潮與巢穴等派系規則，都照該層的派系；換層時跟著換。
- **戰役任務**：維持一局一個派系，不受影響。
- **存檔**：目前 `facilityFaction` 是整局的欄位。改成逐層後要能正確讀回舊的無盡存檔，做法由 Codex 決定並寫明。
- **不變條件**：
  - 戰役生成不變。
  - 行為一致性基準的無盡樣本會因派系改變而變化，要說明原因，不可整批重錄。
- **相關文件**：[ENDLESS.md](ENDLESS.md)、[FACTIONS.md](FACTIONS.md)，實作後補記。

## 5.2 故事片段的內容檔（使用者自己維護）

- **目的**：使用者在本機用編輯器增刪修改故事片段，不需要透過 Claude 或 Codex（使用者決定）。
- **位置與格式**：放在 `content/stories/`，一段故事一個 Markdown 檔，檔名就是 ID。

  ```markdown
  ---
  id: evacuation-cancelled
  title: 最後一班運輸船
  faction: any
  floors: 1-6
  ---
  最後一班運輸船沒有離港紀錄。有人從內部取消了撤離。
  ```

  - **必填**：`id`（要和檔名相同）、`title`。
  - **選填**：
    - `faction`：legacy、loyalist、rebel、swarm 或 any，預設 any。
    - `floors`：例如 `1-6` 或 `3`，預設 1-6。
    - `price`：預設 100。
    - `order`：解鎖頁的排序。
  - **內文**：front matter 之後的全部文字，可以分很多段。
- **編譯與檢查**（比照 `maps/recipes/` 與 `npm run recipes`）：
  - **編譯**：`npm run stories` 編譯成 `src/story-data.js`，這是產生檔，不手改。開發伺服器啟動與 `npm run build` 會自動執行。
  - **產生檔過期**：測試會檢查產生檔是否跟內容檔一致；不一致就失敗，並提示執行 `npm run stories`。
  - **檢查項目**：
    - 必填欄位；ID 與檔名一致。
    - ID 重複，或用到停用的 ID。
    - 派系名稱、層數格式。
    - 內文長度上限。
    - 禁用詞：`content/stories/_banned-words.txt`，由使用者維護，例如企業名稱。
  - **錯誤訊息**：要寫出檔名、行號與怎麼修，讓不看程式的人也能自己改好。
- **刪除與停用 ID**：
  - 刪掉的故事 ID 要記進 `content/stories/_retired.txt`。
  - 編譯時如果發現有 ID 從內容裡消失、卻不在停用清單，就提示補上。
  - 停用的 ID 不能拿來寫新故事。已經解鎖停用故事的玩家，在解鎖頁看到「已封存」。
- **不影響地圖**：
  - 資料物件的位置照舊由種子決定，增刪故事只改變「撿到的是哪一段」。
  - 戰役生成與行為一致性基準不受影響；同一個種子在不同版本可能撿到不同故事，這可以接受。
- **抽選**：
  - 撿到資料物件時，從符合該層派系與層數、而且玩家還沒解鎖的故事中抽，用種子、樓層與物件做亂數，不消耗戰鬥亂數。
  - 沒有可抽的故事時，照常給點數與廢料，但不附故事。
- **多語言**：預留同名的語言檔，例如 `evacuation-cancelled.en.md`；第一版不做。
- **維護規則**：`content/stories/` 由使用者維護。Claude 與 Codex 只在初次搬移與使用者要求時修改。
- **使用者的流程**：
  1. 在本機編輯 `content/stories/` 的檔案。
  2. 執行 `npm run stories` 檢查；要看遊戲裡的樣子就重開 `npm run dev`。
  3. 提交並推送。Pages 部署前會跑測試，格式錯誤不會上線。
- **初次搬移**：
  - Codex 建立格式與工具時，把現有 6 段 `LORE` 搬成內容檔。
  - Claude 寫 `content/stories/README.md`：怎麼新增、刪除、改內容，欄位的意思與常見錯誤。

## 6. 取消攜行升級與舊檔遷移

- **取消攜行升級**：
  - 彈藥容量回到基礎值加上職業加成。
  - 購買與重置的入口移除。
- **玩家檔案升版**（v6 → v7）：
  - 攜行升級已經花掉的點數，全額退回到 `protocol.balance`（沿用 `carryingSpent` 的算法）。
  - 已解鎖職業重設為起始三職業，使用者決定直接鎖回。
  - 已解鎖故事為空，舊的 `player.lore` 只是單局資料。
  - `unlocks.weapons` 與歷史的 `operator` 欄位：目前沒有武器需要解鎖，要保留還是清掉由 Codex 決定並寫明。
  - 完整備份的驗證同步更新；讀取舊版本前先備份原檔（沿用現有流程）。
- **進行中的戰役存檔**：
  - 角色已被鎖定的存檔：Claude 建議允許打完這一局，之後不能再選這個角色。
  - 存檔裡的攜行等級快照：Claude 建議讀檔時歸零，超出容量的彈藥留在腳下（沿用 `resetCarrying` 的做法）。
  - 以上由 Codex 決定並寫明。

## 7. 閘門（哪些地方要檢查解鎖）

- **部署選角**：只能選已解鎖的職業。未解鎖的顯示鎖定與價格（Claude 介面）。
- **QUICK GAME 與每日任務**：隨機角色只從已解鎖的職業抽。
- **Kill house 街機**：只列已解鎖的職業（Claude 建議）；教學固定士兵。
- **單局存檔匯入**：匯入的角色未解鎖時，比照進行中存檔的處理方式。
- **試玩版**：只有起始三職業，不能購買其他職業，也不產生職業屍體（使用者決定）。做成一份設定，發布試玩版時再開。

## 9. 驗收重點（Codex）

- `npm test`、`npm run build` 通過。
- 戰役生成不變；行為一致性基準只允許第 4 節說明的無盡樣本變化。
- **購買**：
  - 餘額不足、重複購買、儲存失敗時，不扣點數也不解鎖。
  - 成功時扣款與解鎖在同一次寫入。
- **屍體**：互動後立即解鎖；之後陣亡仍保留；全部解鎖後不再出現。
- **故事**：撤離才寫入；陣亡或放棄不寫入；重複撿到不重複寫入。
- **遷移**：v6 玩家檔案的攜行點數正確退回，職業鎖回起始三個，完整備份來回相容。
- **閘門**：選角、QUICK、每日、街機都拿不到未解鎖的職業。
- **模擬**：kill house 不影響解鎖與點數。
- **無盡派系**：同一種子每一層的派系固定，而且會隨樓層改變；戰役仍然一局一個派系。
- **無盡沒有故事片段**：無盡樓層不放資料物件。
- **錯過的屍體**：抽到的職業沒去互動就換層，同一局不會再出現。
- **故事內容檔**：
  - 增刪修改故事不需要改程式。
  - 格式錯誤、ID 重複、用到停用 ID、刪除的 ID 沒記進停用清單、產生檔過期時，檢查失敗並指出檔案與修法。
  - 增刪故事不改變地圖。

## 11. 3.90.0 實作現況

### 地圖與規則

- `UNLOCK_SETTINGS`：demo=false、consecutiveFactions=true、fixedFactionOverride=true、corpseStart=5、corpseStep=.1、corpseMax=.5、corpsePity=4（3.151.0；原為 8、.04、.5，沒有保底）。無盡可以連續抽同派系；明確指定 legacy/loyalist/rebel/swarm 則固定，random 不固定。若將 consecutiveFactions 改 false，依先前樓層選擇排除同派系。
- 有無、位置及職業各用 seed/floor/用途字串的獨立雜湊；不耗戰鬥 RNG。樓層派系在生成前決定，使用同一個 pickable 派系池，因此敵人、頭目、詞條、喊話、蟲潮等都跟著該層。
- 屍體是獨立 `operatorCorpse`，不在 props/enemies 裡，不擋路、不提供掩體、不受傷害。位置選非起點房可達空格，避開敵人、道具、家具、危害及出口鄰格。職業從最新玩家檔案未解鎖且本局未出現者抽，抽到即列 encounteredCharacters。
- 回收採免費互動，須存活、同格或相鄰且 canTouch 成立（不能隔關閉門）。玩家檔案成功寫入後才標 recovered；失敗可重試，不消耗屍體。之後保存本局失敗也不重複給解鎖。
- 無盡所有樓層移除 lore；戰役資料位置、點數與廢料不變。故事在拾取時依派系/層數/未持有且不在 pendingStories 的條件抽選，不耗戰鬥亂數。成功撤離才與結算同一次寫入；死亡、放棄不提交。
- 已停用故事仍可驗證舊的持有/待確認 ID；待確認的停用故事撤離後保留為已封存，不能購買停用項。
- demo 禁止購買和屍體，新的職業選擇固定三個（即使完整玩家檔案已解鎖其他角色）。既有戰役仍遵守允許打完的遷移政策。模擬不產生/取得解鎖。

### 內容編譯

- `npm run stories` → `tools/stories.mjs` → `src/story-data.js`。server 啟動及 build 自動編譯；測試用 check 模式拒絕過期產生檔。
- 初次搬移 6 段原文到 content/stories，正文未改；預設價格 100，原樓層 1–6。之後這個目錄由使用者維護，README 留給 Claude。
- 一行一個 front matter 欄位；id/title 必填、faction/floors/price/order 選填。正文上限 12000 字，價格與排序非負安全整數；額外拒絕與職業 ID 撞名。
- ID 刪除必須寫入 _retired.txt；既有停用 ID 不能從清單移除。禁用詞逐行維護、忽略空白與 # 註解，檢查不分大小寫。錯誤均附檔名、行號與修法。
- 編譯器測試不限制內容筆數；規則測試用記憶體故事 fixture，因此未來增刪內容不用改測試。LORE 是產生資料的相容匯出，不能再用樓層索引當解鎖 ID。

## 12. Claude 介面交接

- 目錄：`UNLOCK_CATALOG`（character/story）、`unlockEntry(id)`（停用故事回傳 retired:true）、`availableCharacters(profile)`、`unlocked(profile,id)`。故事正文/標題/price/faction/floors/order 在 `STORIES`；`RETIRED_STORY_IDS` 供封存顯示。
- **購買**：storage `grantUnlock(game,id,'purchase')`，成功回傳已寫入的新 profile，失敗 false（重複、點數不足、demo、模擬或儲存失敗）。必須走此入口，不能先改 profile.balance 再分開寫解鎖。
- catalog 的同名 grantUnlock 是純交易準備：回傳新副本或 false，不寫入；storage 與撤離結算均使用它。介面應呼叫 storage 版本。
- **建立遊戲**：storage `startCampaign({seed,character,portrait,mission,options})`、`startKillhouse(options)` 有規則閘門；controller 部署、QUICK、每日、街機已接上，只列已解鎖者。底層 Game/createKillhouse 保留給引擎、模擬器和 QA，不是玩家選角入口。
- **本局連線**：`connectUnlocks(game)` 綁定目前 profile 的讀取及原子寫入。loadGame/startCampaign/匯入入口已接；若 Claude 新增換 Game 的入口，也要綁定。綁定放 WeakMap，不序列化函式。
- **屍體**：`g.operatorCorpse` 為 null 或 `{x,y,character,recovered}`。外觀可用 `classSpriteRect(character,true)`；只畫已探索範圍，回收後可消失或壓暗。可互動條件用 `!recovered && g.canTouch(corpse)`；呼叫 `g.recoverOperator()`，成功後正常 update/saveGame。規則免費，不要再包成一個等待回合。儲存失敗會 fail() 記錄原因，屍體保留。
- **故事**：`g.pendingStories` 顯示待撤離；已取得的看 `profile().unlocks.stories`。結算保存後讀最新 profile，不要把未成功寫入的候選結果當永久持有。舊 journal 的本局內容已最小調整為依故事 ID 查詢與跳脫文字。
- 攜行購買/重置按鈕與操作入口已撤下；UPGRADES 暫顯點數及持有數，正式解鎖頁由 Claude 做。不提供已取消升級的假購買。
- **場景**：`node qa/create-unlock-scenes.mjs` 生成 qa/fixtures/unlocks/ 四份完整 QA 備份：v6-refund（退款 780）、locked-run-overflow（重裝兵可續玩、步槍溢出）、corpse（角色屍體在腳下）、extraction-story（六層出口待確認故事）。只在 `?test=1` 用完整備份還原；會替換 QA 進度，不動正式資料。
- 驗收重點：購買成功/不足/重複/儲存失敗；未解鎖角色不能新開但可續玩；屍體解鎖後死亡仍保留；故事死亡丟失、撤離取得；demo；新增/刪除/禁用詞/過期內容檔；手機上的鎖定樣式及屍體演出待介面完成後驗收。
