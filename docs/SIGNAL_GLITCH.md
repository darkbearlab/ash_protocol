# 訊號干擾（3.149.0 實作；2026-09-19 使用者要求）

規則在 `src/signal-glitch.js`，只影響畫面：規則層不讀它，也不存檔，所以可以直接用 `Math.random`。

## 使用者的要求

- 色偏原本是畫面震動的一部分（3.147.0）。使用者：「聽起來獨立出來比較好。」
- Claude 提議的幾處都加：失能、被壓制釘住、技能掃描、升級訊號、生命過低。
- 使用者另外加的：
  - 「玩家移動偶爾」；
  - 「有詞條的敵人在移動、攻擊以及呼吸時偶爾」；
  - 「被攻擊時操作介面」；
  - 「其他時候偶爾畫面物件會抽幾個雜訊一下」。

## 兩種干擾

- **整個畫面**：
  - 紅色與青色（綠＋藍）兩層左右錯開，錯開距離就是強度（像素）；
  - 再隨機挑一到三條橫帶往旁邊撕開，每 50 毫秒重挑一次；
  - 強度每 40 毫秒閃一下（有一格掉到 45%），然後隨時間退掉；幾個同時發生時相加，最多 6；不到 0.75 不做。
- **單一物件**（角色、家具、箱子、地上的東西）：
  - 物件先畫到一張小畫布，切成四條，每 45 毫秒各自往旁邊跳（最多 ±3 × 強度像素）；
  - 再疊上紅、青兩個殘影，左右各錯開 1.2 × 強度像素；
  - 前半段全強度，後半段退掉。

## 什麼時候出現

| 來源 | 種類 | 強度 | 長度 | 頻率 |
| --- | --- | --- | --- | --- |
| 你開槍、爆炸、你中彈、鏈鋸 | 整個畫面 | 對應畫面震動的 0.8 倍（3.147.0 的色偏，照舊） | 同震動 | 每次 |
| 被 EMP／震撼彈弄到失能 | 整個畫面 | 開始 5，之後每 1.1～2 秒一次 3 | 420／160 ms | 失能期間 |
| 壓制到被釘住（3 層以上） | 整個畫面 | 2 | 130 ms | 每 1.8～3.6 秒 |
| 士兵預警、偵察兵訊號斷層 | 整個畫面 | 3.5 | 320 ms | 每次使用 |
| 升級的 INCOMING TRANSMISSION | 整個畫面＋訊息框 | 4 | 520 ms | 每次 |
| 生命低於 30% | 整個畫面 | 2.5 | 110 ms | 每 2.6～5.2 秒 |
| 你移動 | 你自己 | 2 | 150 ms | 12% 的步數 |
| 有詞條的敵人移動 | 那名敵人 | 2.5 | 150 ms | 25% |
| 有詞條的敵人攻擊 | 那名敵人 | 3 | 180 ms | 45% |
| 有詞條的敵人待著（呼吸） | 那名敵人 | 2 | 140 ms | 每 3.5～8 秒 |
| 平常 | 隨機一到三個看得見的敵人、家具、箱子或地上物品 | 1.5～2.5 | 90～170 ms | 每 5.5～11 秒 |
| 你中彈 | 操作介面（下方面板與生命條） | 跳動、紅青錯開、一條掉格 | 280 ms | 每次，比出膛晚 90 ms |

- 「有詞條」只算已經顯形的詞條，干擾不會洩漏還沒發現的詞條。
- 數字都在 `GLITCH_TUNING`。

## 設定

- 設定裡「畫面震動」下面有「訊號干擾：開啟／關閉」，和震動分開。
- 預設開啟。系統設定「減少動態效果」而且從沒改過時，預設關閉；介面的閃動也跟著系統設定關掉。
- 設定存在本機（`ash-glitch`），不進存檔。

## 實作

- Renderer：
  - `addEffects` 從這一步的效果產生干擾（`effectGlitches`）；
  - 每一幀畫完後跑 `glitchFrame`：狀態型的干擾（`stateGlitches`）與整個畫面的干擾（`screenGlitch`）；
  - 單一物件經過 `glitchDraw` 包裝。畫的時候把 `renderer.ctx` 暫時換成一張小畫布，所以任何物件都能套用；
  - 中彈時呼叫 `onPlayerHit`，controller 替操作介面加上 `ui-glitch` 動畫（`expansion.css`）。
- 版面被藏起來、畫布大小是 0 時跳過，避免中斷畫面迴圈。
