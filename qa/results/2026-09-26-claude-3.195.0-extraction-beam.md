# 3.195.0 — 撤離光束照使用者的節奏重做

2026-09-26，Claude。

## 需求

使用者看了 3.194.0 的撤離光束，描述腦中的畫面：
- 1～2 px 很細的光束緩緩往撤離點打。
- 打到後才分出主光束和光暈；主光束擴張到一個地磚寬（3.194.0 稍微超過了），光暈永遠比主光束寬一點。
- 主光束一格寬後等待一小段時間，這段時間幹員 sprite 才消失；然後主光束和光暈收縮，變回 1～2 px 的細光束。
- 細光束不要直接消失，而是多個點點依序消失，有點粒子殘留的樣子；切碎時不要太均勻，不均勻是關鍵。

## 做法

- `EXTRACTION_BEAM`（src/renderer.js）：往下 800、展開 400、停留 600（幹員在第 300 ms 消失）、收回 400、碎散 800 ms，共 3 秒；細光寬 1.5 px。
- `extractionBeam`：
  - 往下：只有 1.5 px 主光束，光束尖端有小亮點，緩入緩出地從畫面頂端打到幹員腳下。
  - 打到後才出現光暈（淡入 120 ms），寬度＝主光束＋2＋max(3, 主光束×0.3)，永遠比主光束寬；主光束從 1.5 px 平滑展開到剛好一格（`tile`）；腳下的光暈池跟著主光束寬度變亮。
  - 收回到 1.5 px 後，碎成光點：每個光點依編號雜湊決定寬 1～3 px、有 35% 是 2～8 px 的短條、間隔多數緊密偶爾很長、亮度 0.3～1、消失時間大致由下往上但加上 ±0.42 的亂序、壽命不一、消失時往上飄 3～17 px 並左右散開。不用亂數，同一段動畫每次一樣。
- controller.endRun：轉暗改成等 `renderer.time` 走完光束（每 80 ms 檢查一次），不用現實時間；頁面藏起來（畫面不更新）時最多多等 5 秒。
