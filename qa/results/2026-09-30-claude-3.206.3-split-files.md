## 做法

- **Game、Renderer（類別）**：入口留類別、建構子與核心；每個主題檔是一個類別，成員**逐字**從原檔搬過去（連同上方的註解行），入口在類別後面呼叫新的 `src/mixin.js`，把方法、getter 與 static 用 class 語法同樣的屬性描述（不可列舉）抄到 `Game.prototype`／`Renderer.prototype`／`Game` 上；同名重複定義會丟錯。`this`、`Game.restore`、`Renderer.prototype.x.call(...)`、`Object.create(Renderer.prototype)` 的測試都照舊。
- **`Renderer.draw`**（原本一個 30 KB 的方法）：照原本的順序切成七層方法，放在各自的主題檔：`drawGround`（地板與地上的東西、煙霧場，回傳牆格）、`drawTelegraphs`、`drawActors`（回傳轉角藏身的敵人）、`drawTargeting`、`drawEffects`、`drawWalls`、`drawOverlays`；`draw` 只剩畫布設定、依序呼叫與撤離光束。每層開頭重算 `c,g,t,half,p`（`draw` 期間都不變）；`drawTargeting` 重算 `pos=this.projectActor(p)`，`drawEffects` 重建同一個 `goreShade`（都是純函式，值相同）。
- **controller（模組，有共用的可變狀態）**：主題檔只放宣告——函式、只用字面值或 `t()` 的常數、只有它自己寫的狀態；載入時不碰 DOM、設定或 controller 的變數（靜態檢查確認）。`controller.js` 留整局的狀態、所有事件監聽（大段的點擊、按鍵、觸控處理）、啟動時要跑的程式、`act`、`modal`、開新局與模擬、備份還原、回放工具與測試掛勾，檔尾一次 `export {...}` 主題檔要用的東西（活的繫結）。匯入的變數不能賦值，所以寫到別人狀態的 13 處改成呼叫擁有者的 setter（11 個在 `controller.js`：`setTitleFlow`、`setDeployDraft`、`setDeploymentFaces`、`setLastStatus`、`setPreviousFloor`、`setHotkeys`、`setHotkeyMap`、`setHotkeyCapture`、`setDeckLayout`、`setDeckPick`、`setCommsMemory`；`setCourseWaiting` 在 comms、`setTerminalDraft` 在 pack）；只有單純的 `x=值;` 敘述才改，參數的求值順序與原本相同。拆 `let` 宣告（例如 `kia`、`bossScene` 跟著場景程式走）只把同一行的多個宣告分開。
- **沒拆的部分**：`controller.js` 的點擊處理（18 KB）、按鍵與觸控處理、整局狀態與啟動程式。它們寫二十幾個設定變數（`entered`、`padLayout`、`vhsFilter`……），搬出去要為每個加 setter、改動大段程式，風險與閱讀成本都比留著高；它們本來就是「把按鈕接到主題函式」的轉接層。`Game.restore`（27 KB）與 `Game.action`（11 KB）是單一方法，沒有再切。
- **自動化**（工具在工作階段的暫存目錄，不進版控）：用 acorn＋eslint-scope 分析每個搬動的成員或敘述用到哪些模組層級的名字，產生主題檔的 import、入口的 export 與 setter；搬完後靜態檢查每個檔沒有未定義的名字、每個具名 import 在來源真的有匯出、沒有對 import 賦值、主題檔載入時只用到 `t()` 與純資料常數。
- **載入順序**：比對 461 個入口（每個 src 模組、測試、qa 與工具腳本）改前改後的模組載入順序（依 import 與 re-export 的原始碼順序做深度優先），完全相同。為此三個入口保留 28 行只為順序的 `import './x.js';   // load order only (3.206.3 split)`（game 10、renderer 7、controller 11；有些模組載入時會登錄東西，例如招式登錄表），其餘搬走後用不到的 import 都刪掉。
- 其他更新：`sw.js` 的 `FILES` 與開啟讀取條的模組數（178 → 198）；讀原始碼的 33 個測試檔改讀整組檔案（`tests/helpers/source.mjs` 的 `sourceFamily`），切片的兩個改成讀單一成員（`memberText`），撤離光束的順序改成實際呼叫 `Renderer.draw` 記下各層的呼叫順序，`tests/enemy-data.test.mjs` 的第 1 版存檔例外跟著移到 `game-save.js`，`tests/replay.test.mjs` 的一行比對改認 `setLastStatus(...)`；`tools/text-inventory.mjs` 的手冊與設定頁改讀新檔；幾個註解裡的檔名（`fire.js`、`fx-sprites.js`、`loot-icons.js`、`course.js`、`boss-scenes.js`、`outro.js`、`enemy-specials.js`）。語言表沒動。
- 新測試 `tests/split-modules.test.mjs`：mixin 的屬性描述與重複定義、兩個類別的成員都在原型上且不可列舉、`Game.restore` 仍是 static、三組檔案的清單、快照工具的用法（不開瀏覽器）。

## 風險

- setter：之後在主題檔裡寫 `titleFlow=true` 這類賦值會在執行時丟 TypeError（匯入的繫結唯讀），只在走到那一行時才發生；HANDOFF 第 4 節寫了規則。
- 載入順序保留的空 import：刪掉可能改變模組登錄的順序；已標註。
- 快照工具的雜湊跟機器的 Chrome 與字型有關，只能和同一台機器的記錄比；CI 不跑它。
- `tools/text-inventory.mjs` 的 controller 中文字數從 386 變 181：舊的單一檔裡 `escapeHTML` 的正規表示式有引號，讓它的字串掃描器之後整段顛倒（把註解算成字串）；拆開後主題檔都掃得正確。手冊與設定頁的統計和改前相同，其他檔不變。
