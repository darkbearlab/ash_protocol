# 完整備份與還原（3.9.0）

設定中的「完整備份」下載 JSON，包含協定點數餘額／累計、武器與角色解鎖 ID、永久攜行等級、任務歷史、每局點數發放紀錄，以及目前進行中的任務。任務已結束時 campaign 為 null。原本的單局匯出／匯入保留，名稱改成「匯出任務／匯入任務」。

「還原備份」先驗證，再顯示日期、點數前後值、攜行等級前後值、紀錄與解鎖數量、任務樓層及回合。使用者確認後，以整份快照替換，沒有加總或跨裝置合併。取消預覽不寫入資料。不同裝置間可用完整備份移轉；本版不含雲端同步。

## 格式

`{format: 'ash-protocol-backup', version: 1, namespace: 'live' | 'qa', createdAt, profile, campaign}`

- profile 為 version 4（六種獨立 upgrades.carrying 等級），接受舊 v2／v3；v3 整組升級退款後歸零。campaign 為 v8 單局物件或 null，接受 v1–v7 遷移；保存敵我被動規則，以及三個預備欄與已學會技能 ID。預覽列出六種等級，見 AMMUNITION.md。
- `src/backup.js` 處理建立與驗證，拒絕未知版本、錯誤欄位、負點數、不完整去重紀錄及不相容任務。最大檔案 5 MB。
- 正式與 QA 備份分開，namespace 必須和目前頁面相符。正式資料不可匯入 QA 做測試；QA fixture 也不可作正式完整備份使用。
- 音效／瞄準顯示偏好、舊遷移備份、先前匯入備份不是本格式的內容；完整備份的範圍是全局遊玩資料與當前任務。

## 寫入失敗與復原

`restoreBackup()` 在改動正式鍵之前，先保存 `ash-backup-before-restore` 與 `ash-restore-journal`。前者可在設定的「下載還原前備份」取得，後者處理中途關閉或寫入失敗。

依序寫入 profile、campaign，完成後移除 journal。失敗時用 journal 還原兩個鍵；如果持續無法寫入，保留 journal 並阻止自動存檔覆寫。下次 loadGame 先重試復原。無法完成復原時，以 journal 中的原任務／全局紀錄供檢視和匯出，並顯示儲存不可用。

重複匯入是還原同一快照，餘額不疊加；快照中的 protocolRuns 也一併還原，所以之後匯入同一單局檔案不會重複領取已發放點數。不同裝置上的分歧進度不會自動合併。

所有鍵都沿用 QA 的 `qa-` 前綴隔離。自動測試包括完整／無任務備份、格式拒絕、同局去重、寫入失敗回退、啟動復原與正式鍵未被改動；瀏覽器的下載、檔案選擇、預覽取消與裝置移轉仍需外部 QA。

3.7.0：預覽與匯出時依備份的 profile 攜行等級套用本局容量，超額彈藥落地保留。單局匯入則以當前 profile 為準。購買攜行升級會同次寫入點數及等級；還原是整份快照替換，會恢復備份當時的購買狀態，不合併後來的升級。

## 放棄任務與重置進度（3.9.0）

設定 → 放棄本局：確認後由 abandonRun 將點數及 outcome:abandoned 結果寫入 profile，移除進行中任務，不加勝場；當前 game.status 改為 abandoned，清除待選模組，不推進回合或敵人。重複放棄不重複記錄。重新部署也會先將進行中的任務記為放棄。

設定 → 重置遊戲進度：確認後由 resetProgress 清空任務、點數／發放紀錄、各種攜行等級、解鎖與歷史，回到尚未開始的新任務。音效、瞄準偏好與舊遷移備份不刪除；不呼叫 localStorage.clear()，不碰其他網站資料。QA 與正式區相互隔離。

兩者皆重用 restoreBackup 的完整備份／復原 journal；失敗會還原原 profile 及任務，成功前不切換目前遊戲。設定可下載「還原前備份」，再由「還原備份」復原；下一次放棄／重置／還原會覆寫這份本機備份，應先下載留存。這是遊戲進度重置，不是清除瀏覽器所有資料。重置後的首頁也有「備份與設定」入口。
