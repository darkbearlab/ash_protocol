# 真實模式、喊話與音效（規格，2026-09-14）

- 狀態：**3.76.0 規則層完成；3.76.1 依使用者審查修正了喊話紀錄、隔板耐久與備份驗證。部署、顯示過濾、泡泡與音效由 Claude 接手。** 決定紀錄見第 6 節。
- 依賴：喊話的呼叫點與敵人名稱查詢來自 [ENEMY_AFFIXES.md](ENEMY_AFFIXES.md)。真實模式的顯示過濾、點數加成與音效可以先做。
- 數值：聽得到的半徑、受創喊話門檻交 Codex；泡泡顯示秒數交 Claude。

## 1. 真實模式

- **部署時選擇並鎖定**，整局不能切換（使用者決定）。存於單局存檔，結算畫面與紀錄要標示。
- **協定點數 +10%**（暫定）。使用者說明：加成很少，所以幾乎是純挑戰。
- 瞄準只顯示**名稱與距離**。名稱包含已顯現的詞條片段與「？」。

**隱藏**：

- 目標卡的生命、命中率、掩體與所有狀態標籤（轉角暴露、壓制、近射加成等）。
- 地圖上的敵人血條與壓制層數點。
- 可破壞物的耐久，包括隔板、門、油桶、家具、巢穴。目標卡、地圖耐久條與戰鬥紀錄都不顯示（第 6 節）。
- 戰鬥紀錄裡的傷害數字。紀錄文字目前由規則層直接寫入數字，需要改成可依模式輸出，或改用結構化資料讓介面決定怎麼顯示（交 Codex）。
- 其他任何顯示命中率的地方。
- **敵人圖鑑不受影響**，照常顯示所有資訊（第 6 節）。

**保留**：

- 所有預告：蓄勢「!」、狙擊手倒數、延遲轟炸與擲彈兵的標記。原則是**不隱藏意圖**。
- 喊話（第 2 節）。
- 玩家自己的生命、彈藥、掩護等資訊。

## 2. 喊話（核心規則，兩種模式都有）

使用者決定把喊話扶正為核心規則，標準模式也有；真實模式照樣保留。

### 2.1 架構

1. **行為樹發出**：在狀態轉換、開始預告、跨過受傷門檻時呼叫喊話，只帶台詞種類，不帶文字。
2. **規則層接住**：
   - 檢查台詞種類是否在白名單。
   - 判斷玩家看得到、只聽得到（半徑內），或兩者皆否。
   - 看不到時只附**大致位置**（所在房間或方向），不附精確座標。
   - 結果放進當下這一步的演出事件，與射擊演出同一機制。

   **藏什麼本身是規則**，所以由規則層決定，兩種模式共用。
3. **介面顯示**：依種類查台詞文字（每種敵人可以有數句變化，用固定規則挑選，不動戰鬥亂數），處理優先度、節流與讀秒。

喊話是一次性的演出事件，不改存檔格式，**也不寫進戰鬥紀錄**：紀錄只記規則結果（第 6 節）。

### 2.2 白名單

只允許粗略狀態，**永遠不含數字**。

| 類別 | 例子 | 優先度 |
| --- | --- | --- |
| 危險預告 | 投彈、衝上去、瞄準中 | 最高 |
| 詞條顯現 | 各詞條的專屬台詞 | 最高 |
| 戰術狀態 | 推進、找掩護、堅守射擊、換彈、包抄 | 中 |
| 受創 | 中彈、傷勢加重、重傷求援、被壓制、動不了 | 中 |
| 感知 | 發現目標、追丟了、搜索中 | 低 |

受創喊話是真實模式下的**粗略血量回饋**（使用者同意）。門檻交 Codex，例如第一次受傷、生命一半以下、四分之一以下。

### 2.3 看得到與看不到

- **看得到**：泡泡在單位上方，清楚，顯示時間較長。
- **看不到、但在聽得到的半徑內**：泡泡半透明，顯示時間較短，**標在大致位置**（房間範圍或畫面邊緣的方向）。不標精確格子，以免變成隔牆透視，削弱轉角規則與士兵預警的價值。
- **半徑外**：不顯示。

### 2.4 節流與讀秒

- 每個單位同時只有一個泡泡；同屏數量有上限；同類台詞有冷卻，冷卻中其他單位的同一句不顯示。**不用「×N」疊加**（第 6 節）。
- **讀秒消失**（使用者堅持，讓畫面在一小段時間後恢復乾淨）。
  - 計時從**演出播到那一步**才開始，不是從規則結算時開始。
  - 渲染時間在分頁切到背景時會暫停，泡泡不會在玩家沒看時過期。
  - 預設：一般台詞 2.5 秒；危險預告與詞條顯現 4 秒（Claude 可調）。
- 喊話不寫進戰鬥紀錄，錯過的泡泡無法回看；讀秒長度要以此為準。

### 2.5 誰會喊

- **敵人**：會。
- **有行動樹的友軍**（召喚物、寵物、機體）：可以喊，**台詞內容擱置**。
- **玩家**：3.163.0 起只說兩種話——無效操作，以及即將造成無效操作的提醒（使用者 2026-09-23 決定，台詞見第 9 節）。

## 3. 音效

- 擊中、落空、擊殺使用可以分辨的音效，沿用 `audio.js` 的播放機制。
- 受傷外觀、命中特效等其他演出：使用者判斷成本過高，**不做**。

## 4. 不變條件

1. 真實模式在部署後不能切換，存讀檔後維持。
2. 真實模式下，目標卡、地圖與戰鬥紀錄不出現生命、可破壞物耐久、命中率、壓制層數與傷害數字。
3. 預告標記在兩種模式都顯示。
4. 看不到的單位，喊話不包含精確座標。
5. 喊話不消耗戰鬥亂數，不改變存檔格式。
6. 協定點數加成只在真實模式的局結算時套用一次。
7. 喊話不寫進戰鬥紀錄（3.76.1）。

## 5. 分工與順序

- **Codex**：真實模式的存檔欄位與點數加成、戰鬥紀錄依模式輸出、喊話接收（白名單、看得到與聽得到的判斷、大致位置）、受創門檻與喊話呼叫點。
- **Claude**：部署畫面的模式選擇、所有顯示過濾、泡泡繪製、節流與讀秒、台詞表、音效。
- **順序**：真實模式的顯示過濾、點數加成與音效可以先做。喊話的呼叫點依賴 ENEMY_AFFIXES.md 的行為樹骨架；也可以先接在現有的決策點上，之後隨行為樹一起搬移（交 Codex 判斷）。

## 6. 使用者決定紀錄（2026-09-14）

1. **敵人圖鑑**在真實模式下**不隱藏**任何資訊。使用者說明：那些資訊玩家可能早就內化了，或自己另外記錄。

以下是審查 3.76.0 之後的決定，見 [審查報告](../qa/results/2026-09-14-claude-3.76.0-review.md)。使用者授權 Claude 直接修改規則層並留下紀錄，於 3.76.1 完成。

2. **喊話不寫進戰鬥紀錄。**
   - 使用者說明：紀錄是規則面的東西，不應該有演出。
   - 審查量到 3.76.0 的影響：喊話占紀錄三分之一；每次行動後的提示條約 19% 顯示喊話，約 10% 把玩家自己的行動結果擠掉。
3. **喊話與原有預告紀錄重複也無妨。** 第 2 項之後這種重複已經不存在。
4. **可破壞物耐久在真實模式也隱藏。**
   - 使用者決定隱藏隔板耐久；範圍依 Claude 提議，套用到所有可破壞物。
   - 規則層：紀錄改寫「受損」。
   - 介面：目標卡與地圖耐久條併入 Claude 的真實模式介面批次。
5. **備份驗證**只檢查真實模式加成不超過該局基礎點數，不綁加成比例（Claude 建議）。
   - 備份是本機檔案，驗證只用來擋損壞資料，防不了手動修改。
   - 如果綁住比例，日後調低加成反而會讓舊帳本匯入失敗。
6. **喊話泡泡不用「×N」疊加**（3.76.5）。使用者實際看過後覺得很怪。
   - 同一單位重複同一句：只延長顯示時間。
   - 1.5 秒內其他單位喊同一句：視為冷卻中，不另外顯示；危險預告不受冷卻限制。
7. **說話者倒下後，泡泡一律在 0.4 秒內淡出**（2026-09-15，3.84.3）。不分台詞種類，不留特例。牆後只聽得到的喊話不知道說話者是誰，維持原本的顯示時間。

## 7. 實作現況（3.76.0，Codex；3.76.1 修正，Claude）

**模組**
- `src/real-mode.js` 管模式鎖定與結算報價。
- `src/callouts.js` 管白名單、接收與方向遮蔽。
- 敵人行為樹、受傷及壓制都接上接收器，不改命中、AI 決策或 RNG。

**存檔**
- 單局 save **v39** 新增必填布林 `realMode`；v38 以下遷移為 false。
- 建立及還原完成後，這個屬性不可寫、不可重定義。
- 換層、封存／返回不會修改這個單局欄位；完整備份直接包入 v39 單局。
- profile 仍為 **v5**、備份外層 **v1**：帳本與歷史只增加可選欄位，舊紀錄缺欄位仍合法，不需要重置。
- 地圖世代維持 10。

**點數結算**
- `REAL_MODE_TUNING.protocolPercent=10`。死亡、勝利、放棄都算結算；加成 = `floor(本局基礎點數 × 10 / 100)`。
- 遊玩中仍只發基礎點數；加成在結算時另外記在 `protocolRuns[runId].realBonus`。
- 同一 runId 再次結算、或匯入舊快照，都不會重發；零加成也會留下結算標記。
- `game.protocol.earned` 維持基礎點數，不把加成寫回去，避免再乘一次。
- 備份驗證要求 `realBonus <= earned`（3.76.1）。

**戰鬥紀錄**
- 格式仍是 `{turn,text,danger}`。`Game.log(text,danger=false,realText=null)` 在寫入時依模式選擇文字；真實模式不保存原本含傷害／命中數字的字串。
- 有替代文字的紀錄：
  - 射擊與近戰落空、敵我受傷、環境傷害、失能、等待與翻越提示。
  - 隔板、矮隔板、隔離門受損：改寫「受損」（3.76.1）。
- 玩家資源與補給等數字保留。
- 引擎的傷害與演出 `damage` 資料仍供規則與音效使用；**介面必須完成顯示過濾**，不可宣稱這一版已完成真實模式視覺。

**喊話**
- 聽得到的半徑 **8 格曼哈頓距離**。半徑外即使視野看得到，也完全不發事件。
- 牆不阻擋聲音；半徑內以 `teamVisible` 判斷看不看得到，包含友軍提供的視線。
- 看不到時一律只給八方向，沒有房間 ID、距離或單位身分。
- 受創門檻：滿血後第一次受傷、跌到 50%、跌到 25%。一次傷害跨過多條時只報最嚴重的一條；死亡不報受創；治療後再次跨線可以再報。不新增永久門檻欄位。
- 首次被壓制、首次跨入不能移動的門檻，也會發語意喊話。
- 戰術／感知狀態轉換用 WeakMap 暫存，所以存讀檔後可能重新報一次。演出節流交給介面；不耗戰鬥亂數、不改單位存檔；事件不序列化。
- 3.76.1 起 `receiveCallout` **不寫戰鬥紀錄**；原本只給紀錄用的中文標籤、方向名與 `calloutLogText` 已移除。

**演出時序**
- `presentAnnouncement` 會把步驟外的語意事件（例如整次射擊後才結算的壓制）納入捕捉；步驟內的事件沿用該步，不會重複。
- 受創泡泡排在彈道到達之後出現；喊話本身不增加動畫等待。

## 8. Claude 介面交接

### 模式與結算

```js
new Game(seed, unlocks, carry, character, portrait, missionId,
  {realMode: true, difficultyOffset: 0}); // 第七參數；不填為標準
const mode = game.realMode; // live game 不可寫，切換必須重新部署
protocolSettlement(game); // {realMode, base, bonus, total}，playing 時 bonus=0
```

- `protocolSettlement` 是規則報價，不是再次發款的 API；結算仍用現有的 `recordResult`。
- 歷史紀錄新增 `realMode`、`protocolBonus`；`protocol` 是實際基礎＋加成。
- 舊歷史缺 `realMode` 時當 false，缺 `protocolBonus` 時當 0。
- 不要在控制器再乘 1.1。

### 喊話事件

從 `planPresentation(...).events[].effects` 裡 `type==='callout'` 的項目接收，**播放到該事件才開始計時**。不要從即時的 game.effects 或 `onEnemyCallout` 提早播泡泡。

```js
// 可見單位，position 是事件當下位置，不追蹤後續移動
{type:'callout', cue:'aim', category:'danger', priority:'high',
 visibility:'visible', actorId:'...', enemyType:'sniper', name:'狙擊手…',
 position:{x:14,y:10}}
// 看不到，刻意不帶 actorId / enemyType / name / position / from / to
{type:'callout', cue:'search', category:'perception', priority:'low',
 visibility:'heard', direction:'east'}
```

- `direction` 有八個值：east / southeast / south / southwest / west / northwest / north / northeast；畫面上方是 north。
- 看不到的喊話請按方向合併；不可從引擎的敵人陣列反查精確座標或身分。
- `name` 用已顯現的詞條查詢，未顯現的詞條不會洩漏。

`CALLOUT_CUES` 匯出所有 cue 及其 category／priority，共五類：

- danger：grenade、bombard、aim、attack。
- affix：affix_fast、affix_infrared、affix_night_vision、affix_suppressor、affix_grenadier。
- tactical：move、cover、hold、reload、flank（reload 預留，目前敵人沒有換彈行為）。
- injury：hit、wounded、critical、suppressed、pinned。
- perception：spotted、lost、search。

**規則輸入與觀察 hook**
- 規則輸入沿用 `game.enemyCallout(actor,kind,detail)`；kind、detail 與 cue 的白名單對應見 `calloutCue`。
- `onEnemyCallout` 只收到**已遮蔽的事件副本**，不再是 3.75 的原始 actor hook，僅供觀察或測試。
- 友軍與玩家目前會被拒絕。

**文字與繪製**
- 喊話**不寫戰鬥紀錄**（3.76.1），紀錄保持 `{turn,text,danger}`。
- 泡泡文字與變體由 Claude 的台詞表負責：不能補數值，選句不要耗戰鬥 RNG。
- `renderer.js` 暫時略過 callout，避免沒有 from/to 的事件被當成彈道繪製。請新增獨立的泡泡流程，並保留「看不到的喊話沒有精確位置」這條約束。

### 驗收場景

執行 `node qa/create-real-mode-scenes.mjs`，產生 `qa/fixtures/real-mode-*.json`，每份都經過 `Game.restore` 驗證。只在 `?test=1` 匯入：

- **standard / real**：相同種子與敵人。觀察射擊、受傷、投彈預告：兩種模式結果相同，real 的紀錄沒有戰鬥數字。標準模式的介面若還沒過濾，會照樣顯示數值，這是 Claude 待辦。
- **heard**：完整隔牆，敵人有最後已知位置；等待後只會得到方向喊話事件。
- **distant**：敵人在半徑外；進入半徑前不應產生喊話事件。
- **settlement**：真實模式已有 29 基礎點數，放棄後加 2；重新匯入同一 runId 再放棄，不會重發。

### Claude 介面進度

**3.76.2 部署開關（完成）**

使用者指示：選完任務與行動員後多一步選難度，預留給之後的旋鈕；加一個勾選框，勾了進遊戲就是真實模式。

- 一般與每日任務在選完任務與行動員之後，進入第三步「選擇難度」。
  - 清單來自 `src/deploy-ui.js` 的 `DIFFICULTY_OPTIONS`，目前只有「標準」。
  - 之後做難度旋鈕時，在清單加列即可；偏移量必須通過 `validDifficultyOffset`。
- 真實模式是一個勾選框。開始任務時，`runOptions({difficulty, realMode})` 產生第七參數交給 `new Game`。
- 結算畫面標示 REAL，點數分開寫 `protocolSettlement` 的基礎與加成；最近任務紀錄讀取 `history.realMode`。
- 快速任務不經過這一步，一律是標準。
- 驗收見 [3.76.2 QA](../qa/results/2026-09-14-claude-3.76.2-deploy-step.md)。

**3.76.3 顯示過濾（完成）**

- **目標卡**：`game.realMode` 為真時，`targetDetails` 的結果先經過 `realModeCard`。
  - 只留名稱、完整名稱與距離；生命、命中率、掩體、特性、先後手、狀態標籤都清空，空欄位由 CSS 收起。
  - 超出射程時的「無法射擊／無法近戰」保留，這句不含數字。
- **地圖**：
  - `renderer.enemyBars` 在真實模式不畫敵人血條與壓制點。敵人血條原本在兩處重複繪製，已合併成這一個方法。
  - `objectHealth` 不畫可破壞物耐久。
  - 命中特效不飄傷害數字，MISS 保留。
- **保留**：蓄勢「!」、狙擊手倒數、失能「×N」、所有預告標記，以及玩家自己的資訊。
- **播放中**：演出讀取的是快照，`realMode` 會隨快照複製，所以播放中同樣會過濾。
- 驗收見 [3.76.3 QA](../qa/results/2026-09-14-claude-3.76.3-display-filters.md)。

## 9. 幹員的對話框（3.163.0，使用者決定 2026-09-23）

使用者：「仿敵人的語音一樣，將一些原本應該出現在 log 區的東西精簡到玩家角色的對話框。」範圍由使用者限定為**無效操作與即將造成無效操作的部分**，台詞也由使用者訂：

| 情境 | 幹員說 |
| --- | --- |
| 移動被擋（牆、隔板、敵人、友軍不能換位、影步落點有東西） | 被擋住了 |
| 保險室鐵門（唯一會鎖的門） | 上鎖了 |
| 壓制中移動、換層、影步 | 被壓制了 |
| 下錨／解除下錨 | 下錨！／解除下錨！ |
| 下錨中移動、換層 | 下錨中！ |
| 彈匣空了還開火（含盲射、發射器）；**打出最後一發的那一槍**；以上都要還有備彈 | 需要裝填 |
| **裝填把備彈用光** | 最後一個彈匣 |
| 沒有備彈還裝填；**沒有備彈時彈匣空了還開火、打出最後一發**（3.177.5，使用者：用盡彈藥時開火和裝填統一說這句） | 沒彈藥了／No more ammo |
| 彈匣已滿還裝填 | 已上膛 |
| 超出射程（含盲射） | 目標在射程外 |
| 射線內沒有目標 | 沒有目標 |
| 近戰武器裝填、裝備已拿在手上的武器、生命已滿用醫療包、護甲板已滿用噴劑 | 不需要 |
| 道具或投擲物用完 | 〇〇沒了（醫療包沒了、煙霧彈沒了…） |
| 生命不足還打腎上腺素 | 會死！ |

- 規則層只給代碼（`callouts.js` 的 `PLAYER_CUES`），文字在介面（`callout-ui.js` 的 `PLAYER_LINES`），和敵人喊話同一個分工。台詞不含數字，真實模式照用。
- 講出來的無效操作**不寫進戰鬥紀錄**：第 6 節第 2 項「紀錄是規則面的東西」同樣適用——按錯不是規則結果。三個提醒（下錨切換、裝填用光備彈、打光彈匣的那一槍）有真的規則結果，紀錄照舊。
- 泡泡：幹員色邊框、1.5 秒、重複只延長、換句就取代、不計入同屏 4 個的上限。
- 擱置：失能（使用者想做成哀號而不是報告狀況）。沒有台詞的無效操作照舊進紀錄與提示列。
