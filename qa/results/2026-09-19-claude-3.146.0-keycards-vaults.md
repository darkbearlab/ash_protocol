# 3.146.0 鑰匙卡與保險室 — 驗證報告（使用者決定，Claude 實作，2026-09-19）

## 使用者決定

回覆 Claude 對鑰匙與不可破壞的門的分析：

1. 「A 方案，看機率，三分之一吧。」
2. 「高稀有物品，看是要另外維護一個高稀有度的清單還是怎樣。」
3. 「給菁英可以，不過鑰匙的圖案要特別，或許一個有朝上光柱的光點？（事實上我有點想更新現在的圖示表示，先用這個做實驗）」
4. 「對，只給本層的。」
5. 「可以。」（鐵門打開後仍打不壞，之後照一般門開關）

## 改動

- **新模組 `src/vault.js`**，規格見 docs/VAULTS.md：
  - `placeVault`：`generate()` 最後一步，挑隔間、鎖門、選攜帶者、放保險箱；
  - `VAULT_LOOT`：高稀有清單；
  - 另有開門、掉落、撿取、用不上時換成廢料、存檔驗證。
- **隔間的條件**（生成時）：
  - 一扇門關上就隔開的小隔間，最多 6 格；
  - 裡面沒有起點、出口、敵人、地上物品，也沒有任務目標、終端、軍械武器的預留位置、巢穴；
  - 要有一格不是設施的空地放保險箱。
- **機率**：
  - 符合條件的樓層擲 41%，每一步都用自己的雜湊；
  - 實測第 1～6 層 32.8%、第 7～12 層 7.2%，種子 1～60。
- **`src/world.js`**：
  - `reachable` 加 `keys` 選項，預設把鎖著的門當牆；
  - `generationSafe` 傳 `keys:true`。
- **`src/game.js`**：
  - 各處門的行為：
    - 開門與走進門：沒有本層鑰匙卡就拒絕，不花回合；有的話解鎖、用掉；
    - `setDoor` 不開鎖著的門；
    - `canRoute` 不穿過鎖著的門；
    - 互動鍵顯示「鐵門上鎖」或「刷鑰匙卡」；
  - 物品與掉落：
    - 攜帶者死亡時掉鑰匙卡；
    - 撿起鑰匙卡、外骨骼；
    - 開保險箱時，用不上的東西換成 45 廢料；
    - 保險箱的電漿步槍保留指定的詞條（`registerWeapon` 讀 `affix`）；
  - 進入樓層時提示；
  - 存檔 SAVE 67 與驗證。
- **其他模組**：
  - `src/allies.js`、`src/civilians.js`、`src/movement-boundaries.js`：鎖著的門不能開、算邊界；
  - `src/barriers.js`：驗證三個新欄位，`barrierName` 對鐵門寫「保險室鐵門」；
  - `src/containers.js`：新箱種「保險箱」，內容只能是清單上的東西，不會被做成詭雷箱；
  - `src/data.js`：補給名稱「鑰匙卡」，SAVE 67。
- **介面**：
  - `src/renderer.js`：
    - 地上的鑰匙卡：光點加一道朝上的光柱，會呼吸閃爍，沒有方框；
    - 攜帶者頭上一道小光柱；
    - 鐵門疊鋼灰色，鎖著時有金色掛鎖，不畫耐久條；
  - `src/target-card.js`：攜帶者寫「攜帶鑰匙卡」；
  - `tools/text-play.mjs`：`=` 是上鎖的鐵門，門的清單寫「保險室鐵門上鎖」，狀態列顯示「本層鑰匙卡」。

## 驗證

- **新增 `tests/vault.test.mjs`**，9 個：
  - 第 1～6 層約三分之一有保險室，每一間都符合隔間條件；
  - 有菁英時由菁英攜帶；
  - 清單的每一種都會出現（含三種詞條）；
  - 沒有鑰匙卡時，保險室的格子一律算不到；
  - 鎖著時：沒卡或別層的卡都打不開，`setDoor` 與尋路都不通，子彈與爆炸打不壞；
  - 攜帶者死亡掉卡，撿起、開門解鎖、卡用掉，之後照一般門開關，仍打不壞；
  - 保險箱：外骨骼滿 50 護甲板、重裝兵與已有一件時換廢料、電漿步槍保留貫穿、攜行擴充學習資料；
  - 存檔往返，以及六種偽造與舊存檔；
  - 可以放保險室的樓層比例。
- **修改的測試**：
  - SAVE 67 的釘選；
  - `tests/barriers.test.mjs`、`tests/containers.test.mjs` 的可達性改用 `keys:true`，因為鑰匙卡就在該層；
  - `tests/runtime-enemies.test.mjs` 的敵人比對略過 `keycard`，補給守恆略過保險箱。
- **`npm test`**：**1182 通過**。`npm run build` 通過。
- **identity**：
  - 差異：generation 109、missions 110，機器人 24 個相同；
  - 逐項複製進基準線後：`identical to baseline { generation: 780, missions: 110, bots: 24 }`。
- **identity 的證明**：暫存副本裡把保險室機率設成 0：
  - generation 全部和舊基準線相同；
  - missions 110 項的差異全部只有 `player.keycards: []`；
  - 副本到新版有 36 個任務不同：
    - 21 個是保險室樓層：鐵門三個欄位、攜帶者、保險箱、進入提示；
    - 15 個是第 3、6 層的快照：身分檢查先載入第 1 層，那一層有保險室，所以紀錄裡留著第 1 層的進入提示。
- **瀏覽器**（`?test=1`，手機直向）：
  - 預覽窗格在背景時無法截圖或點擊。改用頁內的 `Renderer` 另外畫一張離屏畫布，再傳回暫存資料夾檢視；
  - 種子 5 第 1 層：
    - 進入提示出現；
    - 鎖定攜帶者時目標卡寫「攜帶鑰匙卡」；
    - 互動鍵寫「南側鐵門上鎖」；
    - 按下去被拒絕，沒有花回合；
  - 離屏畫面：
    - 鐵門有金色掛鎖；
    - 地上的鑰匙卡是光點加光柱；
    - 攜帶者頭上有小光柱；
    - 給鑰匙卡、開門後，紀錄是「用鑰匙卡打開了保險室的鐵門。」，門打開，看得到裡面的保險箱；
  - 開門後的紀錄原本寫「隔離門已開啟」，已改成用「保險室鐵門」的名稱。

## 暫定、待實玩

- 鑰匙卡的光柱與攜帶者的小光柱是新圖示語言的實驗。
- 保險箱目前的外觀和一般補給箱相同（只有名稱與顏色設定不同）。
- 清單內容與 45 廢料的替代值是 Claude 暫定的。
