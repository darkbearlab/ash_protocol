# 3.109.0 摺疊掩體 — 驗證報告（Claude，2026-09-16）

## 使用者定案

第一版提案是「放在面朝的那一格」，使用者否決：「不行 要可以選擇部署位置 不然想往後放還要多花兩回合轉身 除非是改成設置在邊線上的半掩體 不過半掩體是可以翻越的 反而也不會卡死」。追問後選定**用方向鍵選四邊**。

兩件事因此一起解決：往後架不再需要轉身；而半掩體可翻越，所以**不需要連通性檢查**——這東西本來就封不死路。

## 規則層

- 架起來的是既有的 `low_partition`，沒有新型別：HP 60、給掩體、不擋視線與射線、可翻越（翻越者到自己下次行動前被射擊命中 +20）。玩家、友軍、平民、敵人的尋路都早就支援翻越。
- `Game.action('deployCover',[dx,dy])` 架在玩家與該側鄰格之間的邊線上，耗 1 回合，扣一個 `player.barricades`，並讓玩家面向該側。
- `deployCoverReason(game,arg)` 是唯一的拒絕來源，驗證、結算與介面共用：沒有存量／方向不是四個正交之一／那一側不是平地／那一側已有活著的障礙物／邊線數已達 `BARRIER_LIMIT`（256，就是讀檔驗證一直在用的上限，這次把它取名匯出，以免規則寫出一份讀不回來的存檔）。
- 殘骸（hp 0）可以就地重建，沿用原 ID 與原邊線、就地覆寫而不是追加，所以邊線清單不會長出重複鍵或重複 ID。

## 介面

- 按道具鍵 → `renderer.mode='deploy'`，四顆方向鍵與道具鍵、右下鍵一起變成待命色，訊息列寫「按方向鍵選一側架設掩體；再按道具鍵取消。」
- 按方向鍵完成，按道具鍵或右下取消。**架設失敗不離開設置狀態**（`act` 對 `deployCover` 不自動取消瞄準），所以按錯邊可以直接改按另一邊。
- 借用道具鍵標籤時會把原標籤存回去：新的 `slotLabel(view,category)` 是預備欄標籤的唯一寫法，`update()` 與 `updateAim()` 共用，避免退出設置狀態後按鍵卡在「取消設置」。（第一次實作就是這樣壞的，瀏覽器實測抓到。）
- 背包道具分頁的「使用」鈕對 `aim:'side'` 的道具改成關背包並進入設置狀態，而不是直接執行。
