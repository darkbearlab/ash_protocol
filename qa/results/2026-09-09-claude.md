## 測試環境與其限制（下一位請先看這段）

| 項目 | 內容 |
| --- | --- |
| 瀏覽器 | Claude Code 內建瀏覽器面板（Chromium 核心），以 CDP 覆寫視窗尺寸模擬手機 |
| 真機 | **無**。沒有 iPhone 或 Android 實機，所有手機相關結論都是模擬 |
| 操作方式 | 面板處於隱藏狀態，指標點擊會逾時，因此改用 `element.click()` 與合成事件驅動 |

兩個必須知道的環境假象，否則會誤判：

1. **隱藏分頁的 `requestAnimationFrame` 完全停擺。** `controller.js` 的 `fitLayout` 掛在
   `ResizeObserver` → `requestAnimationFrame`，所以改尺寸後版面不會自己重排。
   我第一次在 320×568 量到「canvas 仍為 373px、x=−26、橫向溢出」，一度以為是缺陷；
   補發一次 `window` 的 `resize` 事件後立刻變成 262×262、無溢出，與 Codex 上一輪的數字一致。
   **這是工具假象，不是遊戲問題。** 真機旋轉與網址列變化都會發出 `resize`，會直接呼叫 `fitLayout`。
2. **合成 `.click()` 沒有使用者手勢**，因此 console 會出現
   `Blocked call to navigator.vibrate...`。程式有 `navigator.vibrate &&` 防護，
   真機真實觸控不會有這個錯誤。同樣地，`willReadFrequently` 警告來自我自己的 `getImageData`。

## 三、發現（請使用者決定是否處理，我未改動程式）

### A.【中】「多種互動並存 → 選單」在第 1 層結構上無法觸發

掃描 3000 顆種子的第 1 層初始佈局：

| 兩點之間 | 最短曼哈頓距離 |
| --- | --- |
| 地面武器 ↔ 終端 | **6**（2258 顆為 6、742 顆為 7） |
| 地面武器 ↔ 電梯 | **15** |
| 終端 ↔ 電梯 | **5** |

要讓選單出現，需要兩個互動來源同時落在玩家 1 格內，也就是兩者相距 ≤2。
第 1 層每層只有 **1 把**地面武器，實測 3000 顆種子**沒有任何一顆**做得到。

唯一會再產生地面武器的是 `src/game.js` 的
`if (e.type === 'warden') this.items.push({..., type: 'weapon', weapon: 4})`，
也就是**第 3 層封鎖官陣亡時掉落**。因此這個選單只可能在第 3 層以後、
且封鎖官剛好死在終端或電梯旁邊時出現。

**給驗證者的建議：** 別在第 1 層花時間找這個情境。要驗它就打到第 3 層，
把封鎖官引到終端或電梯旁邊再擊殺，然後站到掉落物與終端之間。

### B.【低】拾取與下樓在瀏覽器自動化下難以走到

第 1 層玩家固定從 (5,5) 出發，電梯固定在 (21,21)。
地面武器距起點約 17 格、電梯 32 格，而第 1 層有 25 名敵人，
暴露狀態下每回合承受約 19 點傷害。以腳本點擊移動幾乎必定中途陣亡（我死了一次）。
真機驗證時建議分兩趟、善用牆角掩護，或直接把「拾取」與「下樓」列為真機專屬項目。

補充：不同種子的地圖、掩體、終端與敵人配置**都不一樣**（6 顆抽樣種子全部相異），
但玩家起點與電梯位置固定，物品只在固定槽位附近小幅位移，
所以上述距離在各種子間幾乎是常數。

### C.【低】未能實際斷網測試離線重開

我嘗試把建置後的 `dist/`（與正式站同一份雜湊 `517b82995f0f`）用 `server.mjs` 跑在
`http://localhost:5173`，再停掉伺服器重載以測真離線。
但這個瀏覽器面板在 localhost http 下**拒絕註冊 Service Worker**
（`Failed to register a ServiceWorker ... An unknown error occurred when fetching the script`），
即使用 `curl` 取得 `sw.js` 是 200 且 MIME 正確。正式 HTTPS 站則註冊正常。

因此離線只驗到「快取內容完整、`fetch` 失敗時會回退 `caches.match`」，
**沒有真的拔網重開**。請真機用飛航模式補這一項。
