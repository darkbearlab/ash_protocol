# 3.198.4 — 再次開啟更快

2026-09-28，Claude。

## 需求

- Claude 解釋了「每次開啟都向伺服器確認每個檔案」與「帶指紋的檔案直接用本機的」的差別。
- 使用者：「好 那來改 改完推上去吧」。

## 做法

- **`sw.js`**：頁面載入以外、網址帶 `?v=` 的請求，先查這一版的快取，有就直接回傳；沒有才上網，拿到後存起來。
  - 其餘請求照舊先上網：主頁面（包括帶 `?v=` 的舊書籤）、`sw.js`、圖片、聲音，以及開發伺服器沒有指紋的檔案。
  - 指紋是打包時由全部原始碼的內容算出來的，內容一改網址就換，所以不會拿到舊檔。
- **讀取條**：3.198.3 放在 `<body>` 裡、樣式表之後的內嵌腳本，會等樣式表（連同 Google Fonts）載完才執行，卡住頁面解析，程式檔也跟著晚開始載。
  - 在本機高延遲測試中，程式檔要到 3.85 秒才開始載。
  - 現在移到 `<head>`、所有樣式表之前：它會立刻執行，等開啟畫面解析出來再更新。
  - 讀取條和數字在開始計數之前保持隱藏，所以不支援的瀏覽器只會看到原本的 INITIALIZING。
  - 3.198.3 沒有單獨推出，線上從沒有這個延遲。

## 驗證（Claude 自己跑的）

- **`tests/offline.test.mjs`**：新增一項。
  - 已快取的帶指紋檔案不會發出網路請求；
  - 沒快取的會上網一次、之後就用快取；
  - 沒指紋的圖片照舊上網；
  - 帶 `?v=` 的頁面載入照舊先上網。
  - 原本的離線測試全部通過。
- **`tests/boot-progress.test.mjs`**：讀取條的監看程式在所有樣式表之前，而且頁面上只有這一段內嵌腳本。
- **再次開啟實測**：
  - 設定：本機打包版，用 Python 靜態伺服器提供 `/ash_protocol/`；無頭 Chrome 手機尺寸，第一次開啟後等 Service Worker 啟用，再重新開啟。
  - 對照組：同一份打包、只把新規則關掉。

    | 情境 | 舊 | 新 |
    | --- | --- | --- |
    | 瀏覽器快取開著，慢速 4G | 0.58 秒 | 0.23 秒 |
    | 瀏覽器快取開著，高延遲（400 ms、400 kbps） | 0.66 秒 | 0.20 秒 |
    | 瀏覽器快取關掉，慢速 4G | 1.68 秒 | 1.27 秒 |
    | 瀏覽器快取關掉，高延遲 | 4.37 秒 | 3.92 秒 |

  - 快取關掉時，Google Fonts 的樣式表每次都重抓，遊戲程式要等它載完才會執行，所以兩者都慢。
  - 開發工具的網路節流不一定作用在 Service Worker 自己發出的請求上，所以舊版的實際成本可能比表上高。
- **其他檢查**：
  - 完整 `npm test` 1378 通過、0 失敗；
  - `npm run build` 成功。

## 還沒處理
