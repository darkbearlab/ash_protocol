## 結論

**未發現缺陷。** 432 項 Node 測試與 build 通過，80 個預快取入口 0 缺件，與 Codex 宣稱一致。

一句話評價設計：**下錨的實作比原提案更好**。使用者原本的描述是「攻擊執行兩次」，
Codex 做成「**在普通與緩速兩個階段各行動一次**」——
玩家射一次、普通敵人反擊、玩家再射一次。同樣是兩次輸出，但敵人夾在中間，
變成有代價的取捨而不是單純的傷害翻倍，而且完全複用既有的 `initiativeQueue`，沒有新開一套結算。

**實作核對（讀碼）**：`doubleAttack` 的條件是
`skillActive(p,'anchor') && ['fire','bumpMelee'].includes(type)` ——
白名單而非黑名單，所以任何未來新增的行動預設**不會**被加倍，這個方向是對的。

佇列做法是把玩家原本的項目改成 `speed:1`，再插入一個 `speed:0` 的 `anchorExtra` 項目後重排，
因此順序為「玩家（普通）→ 普通敵人 → 玩家（緩速）→ 緩速敵人」，與紙條第 3 點描述一致。

兩個容易漏掉的細節，Codex 都處理了：

- **失能只扣一次**：`playerStunned` 旗標讓第二段直接 `continue`，不會重複跑 `skipDisabled`；
  `immunityBefore && !anchorExtra` 也保證免疫每輪只遞減一次。
- **著彈修正不重複累積**：第二段執行前把 `fireChain` 還原成行動前的快照，
  所以同一個世界回合的兩段共用同一層修正，與既有「同輪連發只算一次」一致。

### 3.35.3 按鈕文字

**實測線上量測**：技能鈕文字為「◇ 下錨 啟動」，
高度 **66px、文字行高 13px**，與開火／裝填／破片彈／醫療包／互動**完全相同**，
沒有因為多字造成的換行。320px 下無橫向溢出。

`skillStatus()` 對 toggle 技能回傳 `解除`／`啟動`，`aria-pressed` 由 `skillActive()` 驅動，
背包說明仍保留完整耗時資訊（`entry.text` 未被精簡）。

## 斜角開關門（3.35.2）

`canOperateDoor(b)` 的判定：正面相鄰，**或**站在任一門前格的側向鄰格，
且該門前格可通行、玩家到它之間沒有阻隔。

| 情境（門在 (10,10)–(11,10)） | 結果 |
| --- | --- |
| 正面 (10,10)、(11,10) | ✅ 可 |
| 四個斜角 (10,9)、(11,9)、(10,11)、(11,11) | ✅ 皆可 |
| 同軸 (9,10)、(12,10) | ✅ 皆不可（符合紙條範例） |
| y 軸門的四斜角與兩同軸格 | ✅ 對稱成立 |
| 門前格是牆 | ✅ 不可 |
| 玩家與門前格之間有固定隔板 | ✅ 不可 |
| 已摧毀的門 | ✅ 不可 |
| 斜角開門／關門 | ✅ 各耗 1 回合、**人留原地** |
| 方向標籤 | ✅ 斜角產生複合方位（南／北側 + 東／西） |
| `nearbyDoors` | ✅ 只列出真的可操作的門 |

**沒有追加任何防禦或無敵**：`setDoor()` 未改，開門後仍照原視線、掩體與速度結算。
