# 故事內容檔使用說明

這個資料夾放遊戲裡的故事片段。一段故事一個 `.md` 檔，用編輯器直接新增、修改、刪除，不需要改程式。這個 README 本身不會被當成故事。

> **3.200.0 起**：紀錄平常在「設施紀錄編輯台」（<https://claude.ai/artifact/3De9qdcEpmqh7qDJqPBa6D>）寫：標題、派系、內文與管制員評論。寫好後跟 Claude 說「套用設施紀錄」，Claude 會寫成這裡的檔案、翻好英文、安排樓層與排序。也可以照下面的格式直接改檔案。

## 快速開始

1. 複製一個現有檔案，例如 `evacuation-cancelled.md`，改成新檔名，例如 `night-shift.md`。
2. 把開頭的 `id` 改成和檔名一樣：`night-shift`。
3. 改 `title` 和內文。
4. 在專案資料夾執行 `npm run stories`。
   - 沒有任何訊息就是成功。
   - 有錯會顯示「檔名:行號: 怎麼改」，照著改完再執行一次。
5. 想在遊戲裡看：重新啟動 `npm run dev`。
6. 提交並推送，記得連同 `src/story-data.js` 一起提交。GitHub Pages 部署前會跑測試，格式有錯就不會上線。

## 檔案格式

```markdown
---
id: night-shift
title: 夜班交接
faction: rebel
floors: 2-4
price: 100
order: 7
---
第一段內文。

空一行就是新的段落。

=== COMMS ===
egret/serious: 白鷺的評論。
wren/worried: 鷦鷯接話。
overseer: 監視官沒有臉，不寫表情。
```

- **front matter**：第一行剛好是 `---`，欄位寫完後再一行 `---`。中間一行一個欄位，寫成「欄位: 值」。
- **內文**：第二個 `---` 之後的全部文字，1–12000 字。
  - 空一行分段；只換行不空行，遊戲裡也會換行。
  - 內文是純文字：Markdown 語法（粗體、連結）和 HTML 都會照原樣顯示，不會轉換。
- **管制員評論**（3.200.0，選填）：內文後面一行剛好是 `=== COMMS ===`，之後一行一句，寫成「說話者/表情: 台詞」。
  - 玩家點開紀錄閱讀時，畫面上方的通訊框照順序播，點一下換下一句。
  - 說話者：`egret`（白鷺）、`wren`（鷦鷯）、`overseer`（監視官，沒有臉，不寫表情）。
  - 表情照 `src/comms.js` 的臉譜：白鷺 serious、gentle、speaking、concerned、worried、alarmed、sad、closed；鷦鷯 neutral、grin、speaking、wink、bored、annoyed、serious、alarmed、surprised、sheepish、worried、smug、laughing、sigh、determined、sad。
  - 一句建議 40 字內，通訊框很窄。
- **英文檔**（3.200.0）：同一個 id 加 `.en.md`，例如 `night-shift.en.md`。
  - front matter 只寫 `id`（不含 `.en`）和 `title`；派系、樓層、價格、排序都跟中文檔。
  - 下面是英文內文；有管制員評論時，英文的 `=== COMMS ===` 要一樣多句，順序、說話者與表情都相同。
  - 英文模式讀英文檔；沒有英文檔的紀錄，英文模式會顯示中文。

## 欄位

| 欄位 | 必填 | 說明 | 沒寫時 |
| --- | --- | --- | --- |
| `id` | 是 | 和檔名相同（不含 `.md`）。小寫英文開頭，只能用小寫英文、數字和 `-`。不能和職業名稱相同（soldier、recon、engineer、necromancer、druid、bulwark、berserker、ninja）。 | — |
| `title` | 是 | 標題。**還沒解鎖時也會顯示**，不要把劇透寫在標題。 | — |
| `faction` | 否 | 只在這個派系的設施出現：`legacy`、`loyalist`、`rebel`、`swarm`，或 `any`（任何設施）。 | `any` |
| `floors` | 否 | 戰役第幾層的資料物件抽得到：單一樓層 `3`，或遞增範圍 `2-4`，限 1–6。 | `1-6` |
| `price` | 否 | 在解鎖頁用協定點數購買的價格，非負整數；`0` 就是免費。 | `100` |
| `order` | 否 | 解鎖頁的排列順序，數字小的在前；相同時照 `id` 排。 | `0` |

## 故事怎麼出現在遊戲裡

- **只在戰役**：撿到資料物件時，從「派系和樓層符合、玩家還沒解鎖」的故事裡抽一段。無盡模式沒有故事。
- **撤離才算**：成功撤離才解鎖；陣亡或放棄，這局撿到的故事就遺失。
- **也能購買**：主選單 UNLOCKS 的故事頁可以用協定點數直接解鎖（3.190.0–3.199.x 凍結期間暫停過；`UNLOCK_SETTINGS.storiesWip` 開著時就不能買）。
- **不影響地圖**：增刪故事不會改變地圖，只改變撿到的是哪一段。同一個種子在不同版本可能撿到不同故事。
- **沒得抽時**：沒有符合條件的故事，資料物件照常給點數和廢料。

## 修改、刪除與停用

- **改標題或內文**：直接改。已經解鎖的玩家會看到新內容。
- **改 `id` 或檔名**：等於刪掉舊故事、再新增一段，請照下面「刪除」處理。解鎖過舊 `id` 的玩家不會自動得到新的。
- **刪除**：
  1. 刪掉那個 `.md` 檔。
  2. 把它的 `id` 加進 `_retired.txt`，一行一個。
  3. 執行 `npm run stories`。
  - 停用的 `id` 不能再拿來寫新故事，也不能從 `_retired.txt` 移除。
  - 已經解鎖這段故事的玩家，會在故事頁看到「已封存」。
- **暫時不想讓它被抽到**：目前沒有「隱藏」欄位。可以縮小 `floors` 或改 `faction`，但玩家仍然可以在解鎖頁購買。

## 禁用詞

- `_banned-words.txt`：一行一個詞，`#` 開頭是註解，例如放真實企業名稱。
- 檢查不分大小寫，整個檔案都會檢查，包含標題與欄位。

## 常見錯誤

| 訊息 | 怎麼改 |
| --- | --- |
| 請用 --- 包住開頭的 front matter。 | 第一行必須剛好是 `---`（前面不能有空白或空行），欄位後面還要一行 `---`。 |
| 請使用「欄位: 值」。 | 欄位名稱用小寫英文，冒號後面空一格再寫值；front matter 裡不能有空行。 |
| 請移除未知或重複欄位。 | 只能用上表六個欄位，每個只寫一次。 |
| 請填入與檔名相同的英文小寫 id | 檔名和 `id` 要一模一樣，只能用小寫英文、數字和 `-`。 |
| ID 與職業重複 | 換一個不是職業名稱的檔名和 `id`。 |
| 此 ID 已停用 | 這個 `id` 以前刪過，換一個新的檔名和 `id`。 |
| ID 重複 | 兩個檔案用了同一個 `id`，改掉其中一個。 |
| 故事 xxx 已刪除，請將 ID 加入停用清單 | 刪檔後要把 `id` 加進 `_retired.txt`；或把檔案還原。 |
| 請保留已停用 ID | `_retired.txt` 裡的 `id` 被刪掉了，把它加回去。 |
| 內文請填 1–12000 字。 | 內文不能空白，也不能太長；太長就拆成兩段故事。 |
| 請移除禁用詞 | 改掉那個詞；如果那個詞其實可以用，調整 `_banned-words.txt`。 |
| 產生檔過期，請執行 npm run stories 並提交結果。 | 改完內容還沒編譯。執行 `npm run stories`，連同 `src/story-data.js` 一起提交。 |

## 注意

- 不要手改 `src/story-data.js`，它是 `npm run stories` 產生的。
- 不要刪掉 `_retired.txt` 和 `_banned-words.txt`；內容可以只有註解。
- 英文檔的檔名是 `<id>.en.md`；找不到同名中文檔、或評論句數對不上時，`npm run stories` 會報錯。
- 這個資料夾由你維護；Claude 和 Codex 只在你要求時修改（docs/UNLOCKS.md 第 5.2 節）。
