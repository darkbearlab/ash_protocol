# 火焰與煙霧精靈圖：給 Codex 的規格

2026-09-29，Claude 撰寫。使用者：「準備替火焰和煙霧接不同的 sprite 圖，開規格讓 Codex 生成，會撤退回現在程式繪製的版本。」

- **用途**：燃燒地板、各種煙霧、排煙口、火焰發射器的噴火，規則見 [HAZARDS.md](HAZARDS.md)。遊戲版本 3.202.0（煙霧、排煙口）與 3.203.0（火）會先用程式繪製上線，這批圖到了再換上。
- **交件**：2026-09-29 Codex 交了第一批，見 [FX_SPRITES_HANDOFF.md](FX_SPRITES_HANDOFF.md)；3.202.0 接上煙霧、格柵與固定的火。
- **煙霧改用煙霧場**（3.202.0）：逐格的 `smoke.png` 拼起來一顆一顆，使用者改要一張大貼圖、只羽化外緣。Claude 用 gpt-image 另外產了 `assets/pixel/smoke-field-v1/`（[HAZARDS.md](HAZARDS.md) 第 5 節、`art/smoke-field-v1/README.md`）。`smoke.png` 留著當讀不到煙霧場時的退路；之後煙的圖以煙霧場為準，不再向 Codex 要逐格的煙。
- **撤退**：遊戲讀不到圖、圖不合格式，或總開關 `FX_SPRITES` 關掉時，照舊畫程式版本。所以圖可以分批交，交一張接一張。
- **不在範圍**：規則、數值、新的效果種類、選單與背包裡的圖示。只交下面列的圖。

## 1. 共同格式

照 [PIXEL_ART.md](PIXEL_ART.md) 的真點陣規則：

- 每格 **32×32**，圖集從左上往右排；座標 `x = 欄 × 32`、`y = 列 × 32`。
- PNG 索引色、**4-bit**，每張圖最多 16 色（含透明，palette index 0 是透明）；色值落在 RGB5 階（0–31 轉回 0–255）。
- Alpha 只有全透明與不透明兩種。煙的半透明由遊戲畫的時候設定（見第 3 節），所以圖本身畫成「以那個不透明度疊在深色地板上會好看」的樣子；要表現稀薄可以用規則的網點。
- 遊戲用最近鄰縮放、關閉平滑。手機上一格大約 20～38px，要在小尺寸仍看得出形狀。
- 俯視角，地板底色大約 `#101313`（style.css `--bg`）。
- **動畫**：每種 4 格，遊戲每秒 6 格循環播放，頭尾要能無縫接回。相鄰格子會錯開不同的起始格（`(x×3 + y×5) mod 4`），不必顧慮同步。
- **拼接**：同一片火或煙會佔好幾格，而且左右上下相鄰。格子邊緣不要畫框線或明顯的邊界，內容不要超出 32×32。

## 3. 遊戲怎麼畫（Claude 接入時照這個）

- **煙的不透明度**：濃煙 0.85、淡煙 0.5、蒸氣 0.6、毒霧 0.55、孢子煙 0.6。Codex 可以在交件時建議調整。
- **目前程式版本的顏色**，可當配色參考：
  - 一般煙 `#abc1cd`／`#d4dfe8`；毒霧 `#8fbf4a`／`#c6e586`；孢子煙 `#9c7d53`／`#c8ad87`。
  - 火 `#cf672c`／`#efa65a`；酸液 `#709a48`／`#b8d473`。
- 煙霧剩幾回合的數字、火光與光照（真光照會把附近照亮）仍由程式畫，圖上不要畫文字或大範圍光暈。

## 4. 交件

照 [LOOT_ICONS_HANDOFF.md](LOOT_ICONS_HANDOFF.md) 的做法：

- 來源圖、提示詞與處理步驟放在 `art/fx-v1/`（`PROMPT.md`、來源 PNG、可重跑的轉檔指令），做法和 `tools/pixelize.py` 一致。
- `assets/pixel/fx-v1/` 放成品、`fx-v1.json`（每張圖的尺寸、格數、色盤、SHA-256）和 4 倍預覽圖。
- 寫一份 `docs/FX_SPRITES_HANDOFF.md`：採用哪一版、哪些是使用者親手改過的、已知取捨。交給 Claude 接入，Codex 不改遊戲程式、不升版、不推送。
