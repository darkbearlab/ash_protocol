## 結論

九項清單中**八項通過**，第 8 項（離線與發布資源）**發現一個實質問題**。

門／隔板、補給箱、生活模組、補給站的規則數字全部與 BARRIERS.md、CONTAINERS.md、
LIVING_MODULES.md 相符；互動選單能正確分辨箱／門／終端並以方位標示，版面全程零推擠。

**唯一實質問題（中）**：Service Worker 的離線回退用 `caches.match(event.request)` 精準比對，
沒有 `ignoreSearch`、也沒有導覽回退。因此**帶查詢字串的入口網址必須自己被線上載入過一次**
才能離線開啟；而版本升級時舊快取被整份刪除，那份紀錄就跟著消失。詳見發現 A。

## 三、發現

### A.【中】離線入口只認完全相同的網址，升級後第一次離線可能開不起來

線上 `sw.js` 的 fetch 處理是：

    .catch(() => caches.match(event.request))

`caches.match` 的 `ignoreSearch` 預設為 **false**，而且沒有任何導覽回退（`mode === 'navigate'` → `index.html`）。
預快取的 `FILES` 只有 `'./'` 與 `'./index.html'`，**沒有任何帶查詢字串的變體**。

實測到的狀態（升級到 3.18 後、尚未在新 SW 下重載時）：

| 網址 | 是否在快取 |
| --- | --- |
| `/ash_protocol/` | ✓ |
| `/ash_protocol/index.html` | ✓ |
| `/ash_protocol/?test=1&v=3.18.0`（當時開著的頁面） | **✗** |
| `/ash_protocol/?v=3.18.0`（正式入口） | **✗** |

重載一次之後，`?test=1&v=3.18.0` 才被 fetch 處理器寫入快取（快取筆數 62 → 63）；
`?v=3.18.0` 因為我沒開過，**至今仍不在快取內**。

**後果**：
1. 版本升級時，`activate` 會刪掉整份舊快取，連同上一版存進去的查詢字串網址。
   玩家若在升級後**第一次就離線**開自己書籤的 `.../?v=3.18.0`，會拿不到回應（網路錯誤頁），
   直到再上線開一次為止。
2. 只用過 `.../ash_protocol/` 的玩家，改用帶版本的網址離線開啟同樣會失敗。
3. README 寫「首次完整載入後核心資產可離線」對**資產**成立，但**入口頁**另有這個條件。

**最小修法**（未實作，供參考）：把回退改成
`caches.match(event.request, {ignoreSearch: true})`，
或對 `event.request.mode === 'navigate'` 回退到 `./index.html`。

**誠實說明**：我沒有實際斷網。上述是「快取內容缺這筆」＋「回退用精準比對且無導覽回退」
兩項直接量測的組合推論。請真機用飛航模式確認一次，尤其是**剛升級後的第一次離線開啟**。

### B.【資訊】升級瞬間會短暫並存兩份快取

第一次載入 3.18 時我量到 `ash-protocol-v3-15-0-...` 與 `ash-protocol-v3-18-0-...` 並存；
新 SW 啟用後舊的即被刪除，之後只剩一份 63 筆。屬正常升級過程，**不是缺陷**，
但它正是發現 A 中「舊網址紀錄消失」的直接原因，記錄下來以免下次被誤判。
