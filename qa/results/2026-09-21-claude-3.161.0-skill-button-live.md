# 3.161.0 技能／道具／投擲鈕：亮暗改用布林值、演出中讀即時狀態 — 驗證報告（使用者回報，Claude 實作，2026-09-21）

## 使用者的話

- 「主動技能那個按鈕現在不知道明明有按下後會生效的技能，但按鈕本身卻是暗的，請確認。」

## 追查

1. 先確認亮暗的規則：三個預備欄按鈕（技能、道具、投擲）永遠可按（3.97.0：沒預備時一按開背包），只用 `.unavailable`（透明度 .45）表示「按了不會生效」；`unusable` 對技能鈕是「`canUseSkill` 為假或失能」。規則上，亮暗應該和「按下去有沒有效」完全一致。
2. 實機（本機、士兵）：預警啟動後連按等待，逐回合讀按鈕——冷卻中穩定變暗，**就緒之後卻一下亮一下暗**（第 6 回合亮、第 7 回合暗、第 8 回合亮……），文字始終是「就緒」，狀態列沒有失能，頁面沒有錯誤。
3. 把 `classList.toggle` 包起來記錄呼叫：每次 `update()` 對技能鈕呼叫 `toggle('unavailable', 條件)` 時，**第二個參數是 `undefined`**。原因：`unusable` 的判斷式最後一項是 `preparedEntry(...).resource && p[resource]<=0`，技能沒有 `resource`，整個 `||` 鏈落到 `undefined`；`toggle` 在第二個參數是 `undefined` 時視同沒給——**每次重畫翻轉一次**。同一回合裡演出的每個事件、`act()`、`endPlayback()` 各叫一次 `update()`，翻奇數次就暗、偶數次就亮，看到哪一幀全憑運氣。冷卻中條件是真正的 `true`，所以穩定。道具與投擲有 `resource`，落成布林值，沒有這個問題。
4. 另一個次要問題（追查途中發現）：敵人回合演出期間 `update(view)` 拿到的是該步驟的快照，而技能冷卻是在敵人回合之後才扣，所以動畫播放中按鈕顯示「生效 1」／「冷卻 N」慢一拍，直到演出結束才跳到即時值。按下去 `act()` 會先 `skipPlayback()` 再對即時狀態執行，所以「按了有效」。

## 改動（`src/controller.js`）

- `b.classList.toggle('unavailable',Boolean(slot&&unusable))`：明確布林值。**這是主因。**
- 三個預備欄按鈕的文字、數量、標題、aria 與 `unusable` 一律用即時的 `game.player`／`game`（`lp`／`lv`）計算，不用演出快照；投擲鈕的數量同樣。生命、回合、狀態列、目標卡照舊跟著演出走。

## 驗證

- **`npm test`**：1231 通過（控制器沒有單元測試）。`npm run build` 通過。identity 完全相同（控制器不在雜湊範圍內）。
- **瀏覽器**（本機 `?test=1`，清過 service worker 與快取，BUILD 3.161.0，士兵）：
  - 修正前：預警就緒後按鈕亮暗逐回合交替；記錄到 `toggle` 的第二個參數全是 `undefined`。
  - 修正後：27 次 `toggle` 的第二個參數全是布林值；「生效 1」「冷卻 4→1」期間穩定變暗，「就緒」期間連續三回合、每回合兩次讀取都亮。
  - 演出中（畫面隱藏時演出停在第一幀，等於「動畫還沒播完」）：按等待後 150 毫秒讀到的已經是「冷卻 4」——修正前同一個時間點讀到的是「生效 1」。
  - 主控台沒有錯誤。
- 這個翻轉從 3.97.0 引入 `.unavailable` 時就存在；使用者現在才注意到，可能是因為 3.159.0 之後預警變得值得按了。
