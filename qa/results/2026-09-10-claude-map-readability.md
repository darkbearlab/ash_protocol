# 地圖美術可讀性：診斷與建議

- 日期：2026-09-10
- 提出者：Claude（Opus 5），受使用者委託評估 3.21.0 的新地圖素材
- 受測版本：**3.21.0**，commit `adb3c4c`
- **未修改任何程式或美術檔案。** 以下實驗全部在瀏覽器 session 內即時套用，事後已還原。

## 一句話結論

素材本身沒問題，問題在**明度階層倒置**：最該被看見的單位是畫面上第二暗的東西，
而馬桶與洗手台是最亮的。修正不需要重畫任何一張圖，只要在渲染時依語意角色上色調。

## 診斷：量化

直接量測 `assets/pixel/terrain-v1/`、`walls-v1/` 與角色精靈的可見像素（亮度為 Rec.709 luma，0–255）：

| 群組 | 平均亮度 | 範圍 | 平均彩度 |
| --- | ---: | --- | ---: |
| 地板 floor（4 張） | **52.4** | 39.8–73.8 | 0.23 |
| 牆頂 cap（8 張） | **50.5** | 34.2–85.3 | 0.24 |
| 牆面 face（8 張） | 38.0 | 29.9–63.2 | 0.24 |
| 物件 prop（12 張） | **80.5** | 55.6–120.5 | 0.22 |
| 角色 unit（8 張） | **47.9** | 40.2–52.9 | 0.37 |

三個問題，依嚴重度排序：

**1【最嚴重】地板與牆頂只差 1.9 級亮度。**
玩家最需要瞬間判讀的資訊是「這格能不能走」，而這兩者在明度上幾乎相同。
目前只有朝南的牆面（38.0）比較暗，但那只佔牆體的一條邊。
彩度也幫不上忙——所有地形都擠在 0.22–0.24 這個窄帶裡。

**2 視覺階層倒置。** 現況由亮到暗是：
`物件 80.5 > 地板 52.4 ≈ 牆頂 50.5 ≈ 單位 47.9 > 牆面 38.0`

戰術遊戲應該是 `單位 > 可互動物件 > 地板 > 牆`。
現在馬桶（120.5）和洗手台（112.2）比敵人（52.7）搶眼一倍以上。

**3 地板內部太吵。** 地板貼圖的亮度標準差 10.8–18.0，加上每格的高對比邊框線，
整個可走區域是一片密集的網格線，跟精靈的輪廓競爭。

## 實驗：在瀏覽器即時 A/B

作法是攔截戰場 canvas 的 `drawImage`，依來源圖集分類套 `ctx.filter`。
三個來源剛好對應三個語意群組：`terrain-v1/atlas.png`（地板＋物件）、
`walls-v1/atlas.png`（牆）、`pixel/atlas.png`（單位）。
`terrain-v1` 內部再依 atlas 的 `sy` 座標分開——**index 0–3 是地板、4–15 是物件**，
所以地板與物件可以分別處理。

試過五個組合，記錄有意義的三個：

| 版本 | 設定 | 結果 |
| --- | --- | --- |
| C | 牆 `brightness(0.45)` | 牆確實變成「不可走」，但材質細節被壓掉，可惜了美術 |
| D | 牆 0.72＋地板降對比＋單位光暈 | 明顯改善且保留細節，但物件仍然過亮 |
| **F** | **見下方數值** | **階層正確，細節保留** |

## 建議：F 組設定

| 語意群組 | 建議濾鏡 | 亮度 現況 → 調整後 |
| --- | --- | ---: |
| 地板 floor | `contrast(0.72) brightness(0.95)` | 52.4 → **69.8** |
| 物件 prop | `brightness(0.80) saturate(0.90)` | 80.5 → **64.4** |
| 牆 cap／face | `brightness(0.72) saturate(0.60)` | 50.5 → **36.4**／38.0 → 27.4 |
| 單位 unit | `brightness(1.30) saturate(1.50)` ＋ 暗光暈 | 47.9 → **62.3** |

關鍵落差的變化：

- **地板↔牆頂：1.9 → 33.4**（17 倍）。這是最重要的一項。
- **物件↔地板：+28.1 → −5.4**。物件從「最搶眼」變成「地板上偏暗的東西」，符合直覺。
- **單位↔地板：−4.5 → −7.5**，光靠明度仍不夠，
  真正做事的是 **1.5 倍彩度**（單位基礎彩度 0.37，是全場最高）**與暗光暈**。

`contrast(0.72)` 那一項值得特別說明：它同時做兩件事——把偏暗的地板往中間灰提，
拉開與牆的距離；並壓低貼圖內部的明暗起伏，讓密集的格線安靜下來。一石二鳥。

單位的暗光暈用 `ctx.shadowColor='rgba(0,0,0,0.9)'; ctx.shadowBlur=8` 即可，
不需要描邊迴圈，效能影響可忽略。

## 落地方式

`src/themes.js` 的 `resolveSprite()` 已經回傳語意 index，`renderer.terrain(role,…)`
也拿得到 role 名稱，所以分類是現成的，不必新增資料結構。建議在 `renderer` 加一張
`role → filter` 對照表，畫之前設 `ctx.filter`、畫完還原即可。

**這是渲染層的色調，不是改圖。** 原始 PNG 完全不動，日後想調整或關掉都只改一個常數表；
也保留了「單看很漂亮」的素材品質。

## 兩個附帶觀察

- **牆面材質的差異在遊戲中幾乎看不出來。** 八張 face 的亮度落在 29.9–63.2，
  但其中六張擠在 29.9–39.6，實際遊玩時 conduit／ribbed／vent／armored 難以區分。
  若這些材質是想傳達資訊（例如危險區），目前的明度差不足以承載；若純屬裝飾則無妨。
- **`floor-restroom`（73.8）比其他三張地板亮 20–34 級。** 走進衛浴模組時整片地會突然變亮，
  套上 F 的設定後這個跳變會更明顯。建議把它往下修到與其他地板同一帶。
