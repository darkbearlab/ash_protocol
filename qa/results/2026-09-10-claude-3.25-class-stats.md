### 3. 命中率：卡片與實際結算 ✅

先確認公式來源一致：目標卡片走 `game.accuracy(player,target)`（`target-card.js:10`），
實際擲骰走 `fireChance()`（`game.js:293`），對敵人時同樣回到 `shotChance()`。
**預估、卡片、擲骰是同一個函式，不可能分歧。**

各項常數實測：`DARK_PENALTY = 40`（`lighting.js`）、掩體 `strong 42／box 35`（`cover.js:13`）。
由此推導並在引擎測試中驗證：

| 情境 | 算式 | 值 |
| --- | --- | ---: |
| Soldier 對暴露靜止目標 | 97+8 = 105 → 截斷 | **99** ✅ |
| Soldier 完整箱掩體 | 105 − 35 | **70** ✅ |
| Soldier 完整牆掩體 | 105 − 42 | **63** ✅ |
| Soldier 暴露暗區 | 105 − 40 | **65** ✅ |
| Recon 對普通目標 | 97 + 0 | **97** ✅（實機卡片實測） |
| 敵人對 Recon 靜止暴露 | 97 − 10 | **87** ✅ |
| 敵人對 Recon 一般移動 | 97 − 10 − 22 | **65** ✅ |
| 敵人對 Recon 符合側身 | 97 − 10 − 22 − 20 | **45** ✅ |

實機另有一次獨立佐證：敵人移動並取得箱體掩護時，卡片顯示 **命中 40%**，
恰為 `97 − 22（移動） − 35（箱體）`，與上表同一組常數吻合。

### 4. 近戰四欄獨立 ✅

- 動力拳基礎命中 `hitChance = 99`（`data.js`）；目標 `meleeEvasion +20` → **79%** ✅
- `rangedEvasion +20` **不會**降低近戰命中（仍 99）✅
- `meleeEvasion +20` **不會**進入射擊結算（`innateEvasion` 仍 0）✅
- 敵人近戰基礎 97，且只讀近戰欄：Recon 的 `+10` 是射擊迴避，近戰仍 97 ✅
- 四個 hook 皆可正負，命中仍限 10–99（`meleeAccuracy +100 → 99`、`meleeEvasion +100 → 10`）✅

## 未能驗證的項目

1. **投擲的畫面呈現（presentation playback）與投擲後按鈕標籤的刷新。**
   引擎層完全正確（EMP 扣除、回合推進、log 寫入，皆從存檔直接讀取確認），
   但瀏覽器窗格在本工具環境中 `document.hidden === true`，Chrome 因此完全凍結
   `requestAnimationFrame`（實測畫布每秒 0 次繪製）。playback 無法推進，
   而 `controller.js:81` 在 playback 期間會擋掉所有輸入，於是投擲後的按鈕標籤停在舊值。
   我覆寫 `document.hidden`、改寫 `requestAnimationFrame` 為 `setTimeout` 都無法讓已停止的
   影格鏈重新啟動。**這是工具環境限制，不是產品缺陷**；同一流程在窗格可見時可正常完成
   （本輪第一次投擲就正常結算）。投擲後的 UI 刷新請以人工或 Codex 本機確認。
2. **背景暫停行為本身**（3.5 導入的 `document.hidden` 閘門）。
   為了讓其他項目能測，我必須覆寫 `document.hidden`，因此無法驗證它原本的行為。
3. **`recon-full` 與 `bright-*`／`melee-hooks` 場景的實機操作。**
   八份 fixture 我都用 `node qa/create-3.25-fixtures.mjs` 產生成功，
   但除 `legacy-recon-v18` 外未逐一從 UI 匯入操作；
   這些場景的規則我改以引擎層測試逐條覆蓋（見上方第 3、4、5 點），
   數值來源相同，但**實機觸控操作路徑未走過**。
