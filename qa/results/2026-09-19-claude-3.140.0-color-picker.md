# 3.140.0 幹員塗裝選色器：色輪、明度與 40% 阻擋 — 驗證報告（使用者決定，Claude 實作，2026-09-19）

## 使用者決定（依據）

- 「調整幹員顏色的功能能不能用色輪和可以調整彩度明度的那種介面來做」；「在設定介面就先不要有那個調顏色的」（3.139.1）。
- Claude 回報可行並提出三個問題，使用者回答：
  1. 「哪一種對既有介面友善就用那種」：用色輪加明度滑桿（理由見 docs/OPERATOR_COLOR.md）。
  2. 「保留，會把選色器介面的游標也改指過去，才好微調自己喜歡的顏色」。
  3. 「在 40% 那邊加一個阻擋，但再拉一次還是拉得過去」。

## 改動

- **`src/operator-color.js`**：
  - 自訂顏色 `#rrggbb` 也算合法的塗裝（`validOperatorColor`、`operatorColor`）；
  - 新增 HSV 換算（`hsvToRgb`、`hsvToHex`、`hexToHsv`）；
  - 新增明度阻擋（`softStop`、`BRIGHTNESS_STOP`）。
- **`src/color-picker.js`（新）**：
  - 選色器的標記（色輪、明度滑桿與 40% 標記、數值、八個色票、帶自訂顏色的隱藏選項）；
  - 依螢幕像素比畫色輪；
  - 拖曳與鍵盤操作、阻擋、色票移動游標；
  - 預覽每幀最多重畫一次。
- **`src/controller.js`**：
  - 部署第 2 步改用新選色器並掛上操作；
  - 預覽改用只放當前顏色的小快取，不塞滿戰場的快取。
- **樣式**：`expansion.css` 加上色輪、游標、明度滑桿（黑到全亮度的底色、14 像素寬的拉桿）、40% 標記和它的閃爍（減少動態效果時不閃）。
- **登記**：`sw.js` 快取新模組。

## 驗證

### 自動測試

新增 `tests/color-picker.test.mjs`，5 個：

1. 自訂顏色是合法塗裝，格式錯誤的被拒絕；色票不變；自訂顏色可以套色。
2. HSV 來回換算誤差在一格內；每個色票換算後都對回自己的色票。
3. 明度阻擋：
   - 70 → 20 停在 40；
   - 40 → 20 可以過去；
   - 41 → 39 停在 40；
   - 已經在下面、或往上拉時不擋。
4. 標記：
   - 八個色票都在，預設勾選正確；
   - 起始位置對應存的顏色；
   - 自訂顏色放在隱藏選項並勾選，沒有色票被勾；
   - 原色讓選色器變暗。
5. 部署畫面掛上選色器；設定裡沒有任何調色控制；`sw.js` 有快取；40% 標記的位置算式。

修改 `tests/screen-tone.test.mjs`：預覽和戰場用同一個濃度，但預覽用自己的快取。

`npm test`：**1137 通過**。`npm run build` 通過。

### 瀏覽器（`?test=1`，本機，375 寬的手機尺寸）

- **畫面**：色輪 168 像素在預覽圖旁邊，明度滑桿在 40% 有標記，八個色票在下方，沒有超出畫面。
- **明度拖曳**：
  - 從 91% 往左拖到底，停在 40%；
  - 再從 40% 拖一次，到 12%，並出現暗房提醒。
- **色輪**：點一下切到自訂顏色，沒有色票亮起。
- **色票**：點「赤紅」，色輪游標和明度都跳到赤紅（色相 6°、彩度 67%、明度 89%）。
- **微調**：從赤紅拖一小段，變成自訂顏色（25°、69%、89%），預覽圖跟著換色。
- **前後切換與開始任務**：
  - 下一步再返回，仍是同一個自訂顏色；
  - 開始任務後，本機設定存成 `#e38846`；
  - 戰場的幹員用這個顏色、完整濃度，戰場快取只有這一個顏色。
- **鍵盤**（在頁面裡掛一份選色器模擬按鍵）：
  - 從 42% 按一下往下到 30，停在 40；再按一次到 30；
  - 從 60% 按住不放經過 40，停在 40；
  - 色輪方向鍵可以調色相與彩度；
  - 選原色時選色器變暗；
  - 連續變動只重畫一次。
- **主控台**：沒有錯誤。
