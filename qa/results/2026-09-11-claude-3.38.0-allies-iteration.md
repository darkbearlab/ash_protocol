## 問題（先實測確認）

使用者要求處理「窄口被玩家或其他友軍佔住而卡點」。改動前用 3.37.0 實測三種卡法：

| 情境 | 3.37.0 結果 |
| --- | --- |
| A. 死路走廊帶兩隻召喚物，玩家回頭 | 前面那隻身後是另一隻，推不動；兩隻都在跟隨距離內不會自己動，**玩家永久出不去** |
| B. 召喚哨兵站在門洞射擊，狗在後面想衝過去 | 狗 8 回合停在門口後方，0 傷害 |
| C. 一格走廊，狗在玩家身後、看得到前方敵人 | 狗原地不動，0 傷害；推動只能把狗往後推，無法讓牠到前面 |

## 使用者決定

「一律換位」，取代 3.36 的推動（使用者 2026-09-11：「照你的建議 做一律換位我們試試看」）。推動因此移除，使用者表示要觀察是否需要以別的形式回來。友軍之間換位依我的建議一併實作。

## 規格（前 → 後）

| 項目 | 3.37.0 | 3.38.0 |
| --- | --- | --- |
| 玩家撞友軍 | 推一格，不通往側邊；四周沒空位就拒絕 | **交換位置**：友軍落到玩家剛離開的格子（一定合法），永不失敗 |
| 被換／被推者 | 放棄一次行動（依速度判斷本回合或下一回合） | 同，改用「本回合是否已輪到」（`slotTurn`，不存檔）判斷，比速度比較更準 |
| 不能操作的情況 | 哨兵、失能、隔矮隔板、下錨、沒空位 | 哨兵、失能、隔矮隔板、下錨（沒空位的情況不存在了） |
| 友軍被友軍擋 | 走到最近可達格後停住 | 做正事時可與擋路友軍換位，條件見下 |
| 友軍被玩家擋 | 停住 | 仍不移動玩家；玩家往後撞牠即可換到前面 |

**友軍之間換位的條件**：

- 只在追擊目標、前往留守點、超出繩索返回時；單純跟隨只排隊。
- 只在「完全沒有更近的格子可走」時才換。
- 對方不是放置哨兵、沒失能、沒有留守指令、本回合還沒被換過。
- 對方換過去後仍在牠自己的繩索內。
- 對方原本在打的目標，換完後仍打得到；本來閒著的不在此限。

**規則邊界**：授權文件「讓路」列允許試做「玩家撞活友軍時付一回合換位」，並列出條件：相鄰且邊可通行、落點合法、友軍可移動／非失能／非哨兵、不越矮隔板、結算重驗、不多送行動、不改全域佇列。以上逐項符合。友軍之間換位屬同列「友軍在自身行動時移到合法空格」「局部重新尋路」的延伸，同樣不送額外行動（發起者用掉自己的行動，被換者放棄一次）。沒有碰敵人 AI、共用公式、`initiativeQueue`。

`qa/ally-scenes.mjs` 新增 K1–K4，分別載入 3.37.0 與 3.38.0 的 `src`：

| K2 門洞被射擊中的召喚哨兵佔住，8 回合 | 狗傷害 0，總傷害 56 | 狗傷害 **98**，總傷害 **138** |

| K3 狗在身後，玩家往後撞狗一次 | 狗傷害 0 | 狗傷害 **51** |

**如實紀錄一次中途修正**：第一版允許單純跟隨時也換位，結果 3.36 的「走廊兩隻召喚物排隊」測試失敗：後面那隻為了離玩家近一格跟前面那隻換位，兩回合後又換回來。改成只在做正事時才換，才加入 K4 確認互換 0 次。

## 測試

- `npm test`：**448 項通過**；`npm run build` 通過。
- 依新規格改寫的 3.36 推動測試（被使用者決定取代）：
  - 基本換位與放棄行動。
  - 原「推不動就拒絕」→「死路仍可換位，帶兩隻召喚物走得出去」。
  - 哨兵／失能／矮隔板／下錨拒絕。
  - 快速友軍放棄下一回合與 `restTurn` 往返。
  - 原「敵人搶走唯一空格」→「快速敵人先讓友軍失能，換位整體失敗、回合照付」。
- 新增：
  - 往後撞狗讓牠到前面。
  - 門洞換位成功，以及會失去射線時不換。
  - 有留守指令的狗不會被其他友軍換開。
- 工具瀏覽器（本機 `?test=1`，375×812）：新開德魯伊自然局，狗在玩家正上方，按「上」。
  - 玩家 (5,5)→(5,4)，狗 (5,4)→(5,5)，回合 1→2，`restTurn=2`。
  - 畫面提示「伴生獵獸與你交換位置，放棄一次行動。」
