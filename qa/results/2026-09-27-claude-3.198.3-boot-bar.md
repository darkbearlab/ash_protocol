# 3.198.3 — 開啟畫面的讀取條

2026-09-27，Claude。

## 需求

- 使用者：「是否可以讓剛進入遊戲的 initialize 的畫面改成反映真實情況的讀取條？」
- Claude 提案後，使用者決定：用檔案數量，文字維持 INITIALIZING。

## 量到的現況（線上版，無頭 Chrome，沒有快取）

- 一般網路：開啟畫面持續約 4.3 秒；慢速 4G：約 10.8 秒。
- 前 1.4～1.9 秒是頁面與樣式表。
- 之後幾乎全是 167 個程式檔（壓縮後 655 KB）。檔案載完到程式跑起來只要約 0.15 秒。
- 圖片與音樂在開啟畫面結束後才載，不在這段等待裡。

## 做法

- `index.html`：
  - 開啟畫面多一條細條與「n / 167」。
  - 在遊戲程式之前加一段小程式，用 `PerformanceObserver`（resource，buffered）數已經載完的 `/src/*.js`（去掉 `?v=` 版本參數），樣式表載完就給 5%。
  - 開啟畫面消失時停止監看。
- **總數**：寫在 `data-modules="167"`。`tests/boot-progress.test.mjs` 從 `src/main.js` 沿著 import 重算，也確認沒有任何動態 import（那會在讀取條消失後才載）。
- **樣式**：`expansion.css` 的 `.boot-bar`、`.boot-count`；不支援時加 `boot-plain`，只留原本的文字。
- 原本 12 秒後出現的「載入時間較長」提示不變。

## 驗證（Claude 自己跑的）

- **`qa/boot-bar-probe.mjs`**（開發伺服器，慢速 4G、關快取，手機 390 寬）：
  - 讀取條從 0 / 167 開始；
  - 樣式表載完時到 5%；
  - 最大的 controller.js 載入的約 4 秒內停在 1 / 167，之後一路跳到 167 / 167（95%），開啟畫面在 16.9 秒時消失。
  - 開發伺服器的檔案沒有壓縮，所以比線上慢。
  - 中途截圖顯示「65 / 167」。
- **打包**：`dist/index.html` 保留 `data-modules="167"` 與監看程式。
- **其他檢查**：完整 `npm test` 1377 通過、0 失敗。
