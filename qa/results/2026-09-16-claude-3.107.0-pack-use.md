# 3.107.0 消耗品直接從背包使用 — 驗證報告（Claude，2026-09-16）

## 需求

使用者定案：「消耗型道具可能變成在背包中也可以直接使用」，因為準備欄那一格要讓給佩戴型道具當生效欄，一格不可能同時是快速取用欄與生效欄。這批只做消耗品，佩戴件與回合成本是下一批。

## 規則層

- `itemUseReason(g,id)`（src/game.js）是唯一的拒絕理由來源，回空字串代表現在可以用：
  - 沒有存量 → `沒有<名稱>`
  - 醫療包：`生命已滿且未中毒`
  - 修復噴劑：`護甲板已滿`
  - 腎上腺素：`失能中無法使用`／`免費移動還沒用完`／`生命不足以承受`
- `validateAction` 的 `heal`／`plate`／`surge` 三支改成查同一個 helper（`ITEM_BY_ACTION` 由 catalog 反推，之後加道具不用再改這裡），所以背包灰掉的按鈕與那一回合真的會拒絕的理由不可能分岔。
- 移除 `type==='heal'&&p.prepared.item!=='medkit'` 的舊守門。手榴彈的 `prepared.grenade` 守門保留，因為那一欄同時決定丟哪一種。

## 介面

- `showInventory` 的道具列多一欄 `.pack-use`（`.pack-row-usable` 把格線從兩欄改成三欄），順序是 名稱／使用／?。
- 有理由時按鈕 `disabled`，理由寫進 `title`；**持有量 > 0 時**才另外補一行 `.pack-reason`，免得每個 ×0 都多一行字。
- 點下去 `modalAction(entry.action)`：先關背包再結算，與其他背包行動（拆解、改裝、拾取）同一條路。
- 分頁提示改成「消耗品可直接按『使用』，不必先預備。點一下預備，再點一下取消，兩者都不耗回合。」

## 順帶修掉的兩個 3.106.0 問題（都還沒發布）

1. **錯字**：`修復噴劊` → `修復噴劑`（U+528A → U+5291），src/game.js 三處、src/prepared.js 兩處。
2. **用完腎上腺素後存檔讀不回來**：`Game.restore` 的驗證寫著 `g.shadowSteps>0&&classPerkRank(p,'ninja_shadowstep')===0` 就回 `null`——免費移動以前只有忍者影步會給。腎上腺素把它開放給所有職業後，非忍者只要在「打完針、還沒走完格」之間關掉遊戲，整局存檔會被判定非法而消失。改成只驗範圍 `0…max(SURGE_STEPS,2)`。這是在瀏覽器實測時撞到的，自動測試原本沒有覆蓋這個時間點。
