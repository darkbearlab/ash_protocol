# 3.149.0 訊號干擾 — 驗證報告（使用者要求，Claude 實作，2026-09-19）

## 使用者要求

- 使用者問色偏的強度怎麼決定。Claude 解釋：強度是畫面晃動量的 0.8 倍，最多 5 像素，所以不晃就沒有色偏。
- 使用者：「聽起來獨立出來比較好。你提議的這幾樣都有雜訊也不錯。」
  - Claude 提議的幾樣：EMP／震撼失能、被壓制釘住、偵察兵訊號斷層與士兵預警、升級的 INCOMING TRANSMISSION、生命很低。
- 使用者追加：
  - 「玩家移動偶爾」；
  - 「有詞條的敵人在移動、攻擊以及呼吸時偶爾」；
  - 「被攻擊時操作介面」；
  - 「其他時候偶爾畫面物件會抽幾個雜訊一下」。

## 改動

- **新模組 `src/signal-glitch.js`**，規格見 docs/SIGNAL_GLITCH.md：
  - `effectGlitches`：一步的效果帶來的干擾，包括開槍、爆炸、中彈、技能掃描、移動、有詞條的敵人移動與攻擊，並判斷這一步你有沒有中彈；
  - `stateGlitches`：看當下狀態，包括失能、釘住、低生命、有詞條敵人的呼吸、平常的隨機物件；
  - `screenGlitch`：整個畫面的紅青錯開與橫向撕裂；
  - `drawGlitched`：單一物件的切片跳動與紅青殘影。
- **`src/renderer.js`**：
  - 色偏不再跟著震動；
  - 新增 `glitchFrame`（每一幀畫完後）、`glitchDraw`（玩家、敵人、家具與箱子、地上物品都經過它）、`glitchBurst`、`onPlayerHit`。
- **`src/controller.js`**：
  - 設定「訊號干擾」開關（`ash-glitch`）；
  - 中彈時下方面板與生命條加上 `ui-glitch`；
  - 升級訊號出現時，畫面干擾加上訊息框閃動。
- **`expansion.css`**：`ui-glitch` 動畫，系統要求減少動態效果時不播。
- **`src/game.js`**：技能的 `pulse` 效果多了 `skill`，只給畫面用。
- **`src/screen-shake.js`**：畫布大小為 0 時不做色偏。

## 驗證

- **新增 `tests/signal-glitch.test.mjs`**，3 個：
  - 開槍、爆炸、中彈照舊產生畫面干擾；中彈才讓介面閃，沒打中不會；
  - 掃描類技能才會觸發；移動偶爾觸發；有詞條的敵人只有在詞條顯形後才會觸發；
  - 失能開始時先爆一下、之後持續脈衝；釘住與低生命各自脈衝；有詞條敵人的呼吸；平常隨機挑物件。
- **修改 `tests/frame-rate.test.mjs`**：畫面迴圈的原始碼釘選。
- **`npm test`**：**1198 通過**。`npm run build` 通過。
- **identity**：`identical to baseline { generation: 780, missions: 110, bots: 24 }`。
- **瀏覽器**（`?test=1`，手機直向）：
  - 離屏畫面：玩家、家具、醫療箱的切片錯位與紅青殘影；升級訊號強度 4 的整個畫面錯開與橫向撕裂；
  - 實際進遊戲走動、開火五回合，主控台沒有新的錯誤。
- **開發中發現**：測試用的離屏畫布移除後大小變 0，畫面干擾的 `drawImage` 會丟例外。真實遊戲在版面被藏起來時（例如直向提示）也可能這樣，而且例外會中斷畫面迴圈。已在 `screenGlitch`、`chromaSplit`、`drawGlitched` 加上大小為 0 時跳過。
