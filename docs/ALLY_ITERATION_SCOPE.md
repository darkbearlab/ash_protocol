# Claude 三職業迭代授權：工程師、死靈法師、德魯伊

本文件依使用者要求建立：三職業目前存在位置難控制、友軍卡點與戰力不足，讓 Claude 可多次修改與驗證，不必每輪經 Codex 審批。這是 `給Claude的交接.md` 的明確局部例外，優先於其中「AI／尋路／友軍規則只能交 Codex」的舊限制。其他系統仍依原分工。使用者後續指示優先。

本次只有規劃與文件，沒有實作以下候選方案。基準為 main 的 3.35.8（d3c4ac4），save v25／profile v4／backup v1；開始每輪仍須 fetch 最新 main，不把此快照當最新版本。

## 目標與建議順序

先讓玩家能把隊友帶到需要的位置、通過窄路，再調整輸出與續航。卡在門後造成的零輸出不應只靠加傷害掩蓋。建議分成可各自發布的三批：

1. **卡點與跟隨**：一格通道、門前、轉角、兩隻召喚物互擋；友軍有替代站位可走時不要因精確目的格被占就永遠停住。讓路、局部重新尋路、穩定優先順序優先。
2. **位置控制**：清楚顯示跟隨／留守／返回／待部署／超距，改善寵物選點；試做工程師部署落點選擇及死靈的全體集合／留守。所有操作要有取消、不可用原因與現有手機介面容納方式。
3. **戰力與成本**：同一批種子比較有效參戰回合、命中、輸出、生存和補給消耗；按職業分開調整。先完成一組有代表性的手測，再決定下一輪，不要求每次打完整局才可修一個卡點。

這是建議順序，不強制一次做完或選定某種 UI；Claude 可依使用者試玩回饋調序。新大系統、其他職業、升級商店接線不在這份授權內。

按行為而非檔名分界。允許修改 `src/allies.js`，以及 `game.js`、controller、renderer、保存驗證等為此所需的最小接線；不要求把規則硬塞進 UI。

## 三職業必須保持的身分

**工程師**：追隨／放置共用一台機體與同一份 HP、ID、失能、彈藥所有權。使用玩家備彈，既有部署／回收裝填機制保持；切型先收納，退彈遵循攜帶上限與落地規則。不憑空補彈或換型回血。損毀可相鄰回收殘骸，收納後花廢料修復；不改成遠端復活或直接贈送替代機體。哨兵原地作戰。

> **2026-09-11 使用者決定（3.39.0 實作）**：取代上段的「損毀相鄰回收殘骸」，改為損毀或留在別層時，花 30 廢料生產新機（直接部署，舊殘骸移除）。另取代下方「需另行討論」清單中的「無人機自動遠端裝填」：機體在玩家 3 步可通路內會自己用玩家步槍彈換彈（花機體自己的行動）。同一決定還包括：追隨模式改用步槍、機體 HP 90、哨兵可利用掩體並有裝甲 5。仍維持單一機體、收納後才能修復、哨兵原地作戰、不自動追擊。規格見 [ALLIES.md](ALLIES.md)「工程師」。

> **2026-09-11 實作紀錄（3.41.0，使用者提出，屬本文件已授權範圍）**：位置控制批次的「工程師部署落點選擇」已實作：部署或生產時在玩家 2 步可通路內的空格自選落點，選點免費可取消，部署與生產仍付原本回合與廢料。距離參數：追隨機體閒置距離 2→1（貼身，方便換位）。追隨機體仍不主動追擊；模擬中讓它追擊的版本沒有更好（見 3.41.0 報告）。規格見 [ALLIES.md](ALLIES.md)「3.41 貼身跟隨與自選落點」。

**德魯伊**：一隻可指揮、可救援的伴生寵物，跟隨／留守差異要可預期。倒地不行動／擋路／提供視野，靠近消耗醫療包與一回合救援。可調回復比例，不增生命連結、傷害轉移、多寵物或免費復活。

> **2026-09-11 使用者決定（3.37.0 實作）**：取代上段的「靠近消耗醫療包救援」與「不增免費復活」。改為倒地後相鄰花 1 回合回收（不耗醫療包）、收納中每回合自行回血、回滿且技能預備中自動歸隊，醫療包改為收納時加速；寵物繩索 9 格。仍維持單一寵物、不增生命連結或傷害轉移。規格見 [ALLIES.md](ALLIES.md)「德魯伊」。

**死靈法師**：從本層實際死亡且未用的非頭目敵人抽選，只補缺額、保留活體傷勢；每具屍體只消耗一次。可調召喚上限及倍率，但不改成理論敵人池、指定召喚物種或重抽現有活體。無合法生成格就少召或不召，不能先吞素材。召喚物死亡／未同行不占名額、無獎勵、不成為再召素材；不新增解除召喚或回收換素材機制。

## 共用不可退步條件

- 全域快／普／慢與同速順序、玩家行動承諾、失能／冷卻倒數不變。部署／召喚／復活的新單位當輪不追加行動；命令不讓單位插隊。修路不能變成一次走完整條路。
- 不永久重疊玩家／敵人／活友軍，不瞬移、不穿實牆／關門／完整隔板；開門與翻越走原規則與破綻。任何換位需要原子驗證，失敗不留下半套座標。
- 分享視野仍需連線與有效視線；不讓玩家藉友軍穿牆射擊，不改煙霧／夜視／紅外線／震撼相互作用。攻擊沿用共用命中、掩體、傷害與 presentation。
- 敵方目標選擇、任務／XP／掉落流程不改。友軍擊殺正常給敵人獎勵；友軍死亡無可刷資源。不能為提升存活取消既有範圍傷害或狀態影響。
- 附近活體可同行，遠處寵物／機體留原層、召喚物消失；收納機體同行。無落點不重疊生成；未載入樓層不偷偷模擬。同行不得刷新 HP／彈藥／失能。
- `game.allies` 唯一所有權、`allySerial` 單調 ID、floor／sourceId／missionId 保持。不得複製到 floorStates。保留 survivor 鉤子；新策略預設只作用 drone／pet／summon，不替未開發的生還士兵事件決定玩法。
- 舊局保留既有傷勢與資源。明列改動只影響新建單位或即時讀取參數；不得載入時重建友軍、免費補滿。降低上限不刪現有超額活體／彈藥，停止新增或使用既有退彈機制。格式需要升版才升版，保留舊原件、遷移與完整備份測試；不重置正式存檔。

需另行討論的例子：每回合多動／多攻、部署改免費、無人機自動遠端裝填、寵物生命連結、跨樓層瞬間召回、全圖感知、新召喚素材來源、敵人全面重寫、通用地形／戰鬥公式改動。列出問題與候選方案即可，別讓它阻擋已授權部分。

## 每輪驗證與回報

以同組種子／同配置比較前後，先小場景、再真人自然局。至少涵蓋一格走廊雙向相遇、L 形轉角、門前塞車、兩召喚物互擋、目的格被占、哨兵擋路、超繩索返回、換層有／無空位。若本輪未改其中行為，沿用已通過回歸，毋須每次重新手測全部。

針對改動測：正常／快速／緩速順序、失能、免費命令不動世界與 RNG、付費失敗原子性、彈藥廢料守恆、屍體只用一次、保存重載指令、舊檔及備份。保留相關 invariant 測試；新設計取代舊行為的測試可以改，但報告說明哪項規格被取代。發布前 npm test 與 npm run build，依 RELEASE 正常整合 main 並確認本次 SHA 的 Pages success。

- 基底／發布版本與 SHA、Pages 結果；本輪只解哪一兩個問題。
