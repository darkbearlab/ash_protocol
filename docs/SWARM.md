# 蟲族第二步：毒液、鉤舌、感染詞條與蟲潮（規格，2026-09-14）

- **狀態**：3.84.0 已實作3.1–3.3；3.4蟲潮已提案，等移動演出合併後另批實作。
- **分工**：規則與精靈圖交 Codex；台詞、預告與演出、數值交 Claude，在 Codex 之後做。
- **前一步**：3.83.0（Claude）已經用資料做出蟲族派系，見 [FACTION_DATA.md](FACTION_DATA.md) 第 16 節。
- **設計來源**：[FACTIONS.md](FACTIONS.md) 第 4 節（使用者構想）與第 10 節第 13 項（決定）。

## 1. 使用者決定（2026-09-14）

1. **頭目**：先用超大型蟲當頭目（3.83.0 已做資料卡）。**鉤舌也寫給它們用。**
2. **掉落**：非蟲潮的蟲族單位照常掉落資源（現在的彈藥掉落規則本來就涵蓋）。蟲族不掉武器，武器只能靠箱子，先觀察。
3. **被感染者**：除了遊蕩者，也保留基本士兵；射擊發數增加、但命中低很多，因為失去了準頭與扳機紀律（3.83.0 已做資料卡）。
4. **遠程壓力**：被感染士兵連發會造成壓制，再加上毒液射擊與近戰，這樣就足夠。

## 2. 3.83.0 已有的東西（不要重做）

- **派系 `swarm`**：
  - 出生池：獵殺蟲（crawler）、被感染槍兵、被感染突擊兵、孢子自爆體、巨型蟲。
  - 頭目：第 3 層巢穴巨獸 `hive_beast`，第 6 層母巢巨獸 `hive_matriarch`。
  - 雜兵是被感染者（fodder），蟲巢固定用地洞樣式，產物是蟲群幼體（brood）。
- **兵種卡的 `combat` 欄位**：出生時複製成單位的 `combatModifiers`。被感染士兵是 `rangedAccuracy:-35`，連發 3、4 發。
- **`nestStyle(p, faction)`**：派系可以固定蟲巢樣式。
- **`PROTOCOL_REWARDS`**：已有兩個蟲族頭目的協定點數。

## 3. 規則（Codex）

### 3.1 毒液噴吐蟲（新兵種卡）

- **卡片**：
  - 代號暫定 `spitter`，名稱暫定「毒液噴吐蟲」。
  - 遠程、生物、沒有裝甲；生命與射程由 Codex 先給暫定值，Claude 之後調。
- **攻擊**：命中時**不造成傷害，改成讓目標中毒**，靠中毒殺傷。
  - 玩家中毒已經存在（`player.poison`），醫療包能解毒、防護升級能抗毒。這一條要讓它們重新有價值。
  - **中毒的疊加、每回合傷害、持續回合、上限**：由 Codex 定，並寫進報告。
  - **友軍與寵物**：會不會中毒由 Codex 決定。不中毒的話，毒液打在友軍身上要怎麼處理也要寫明。
- **出生**：
  - 加進 `swarm` 的出生池：第 1–2 層不出現，第 3 層起 1 份，第 7 層起再加 1 份。
  - 數量之後由 Claude 調。
- **精靈圖**：站姿與倒地各一張，沿用現有敵人精靈的製程；原有圖格的順序與內容不變。
- **彈道外觀**：規則層只要讓攻擊風格可以辨認為毒液（例如新的 `attackStyle` 或 projectile 代號）；彈道畫法由 Claude 接。

### 3.2 鉤舌（給兩個蟲族頭目）

- **效果**：沿用狂戰士鉤鎖把人拉近的邏輯，把玩家拉到頭目身邊。
- **預告**：
  - 必須先蓄勢一回合，並標出拉扯路線，讓玩家有機會反應。
  - 預告的畫法由 Claude 接；規則層提供事件或狀態欄位即可。
- **打斷**：
  - 蓄勢期間，頭目失能、被壓制到無法行動、或死亡時，鉤舌取消。
  - 要不要加上「受到一定傷害就中斷」由 Codex 提案。
- **限制**：
  - 射程暫定 5 格，需要視線，不能穿牆。
  - 路線上有障礙或單位擋住時失敗或不發動，由 Codex 決定並寫明。
  - 冷卻暫定 4 回合。
- **對象**：第一版只拉玩家。能不能拉友軍由 Codex 決定並寫明。
- **資料化**：
  - 用兵種卡欄位或行為分支宣告「有鉤舌」，不要寫死頭目代號。
  - 巨型蟲要不要也有，試玩後由使用者決定，屆時只需改資料。

### 3.3 被感染者的詞條

- **死亡裂出小蟲**：被感染者（士兵與遊蕩者）死亡時，在身邊放出蟲群幼體。
  - 數量暫定 1–2 隻，受 `RUNTIME_TUNING.expendableLimit` 限制，空間不夠就少放。
  - 裂出的幼蟲不掉落、不給經驗，和現在的蟲巢產物一樣。
- **攻擊帶毒**：命中時除了原本的傷害，再讓目標中毒（沿用 3.1 節的中毒規則）。
- **做法**：
  - 建議做成隱藏詞條，沿用現有的詞條系統（名稱、「？」與顯現）。
  - 只適用於帶「感染」標籤的卡片，建議新增 `infected` 標籤。
  - 由 `swarm` 的 `affixWeights` 或卡片資料決定出現機率。
  - 具體做法由 Codex 提案。
- **小菁英**：蟲族的小菁英抽詞條時，能不能抽到感染詞條，由 Codex 決定並寫明。

### 3.4 蟲潮（研究並提案，可以分批）

- **使用者構想**：真的一大堆小蟲淹沒整個通道。霰彈槍的鄰格濺射會因此變得有用。
- **需求**：
  - 陸續出現，不是一次全部生成；沿用增援預告（「+N」倒數格），確保公平。
  - 不佔每層的威脅額度（參考 [CIVILIANS.md](CIVILIANS.md) 第 4.5 節的做法）。
  - 需要一個蟲潮專用的數量上限，不能吃掉現有的 `liveLimit`。
- **Claude 的前置工作**：
  - 現在每隻敵人移動都是一段獨立演出，30 隻小蟲會依序播 30 段。
  - 蟲潮上線前，Claude 會先把「只有移動」的連續步驟合併成同時播。這一項不動規則。
- **報告要寫明**：觸發條件、每波數量、間隔、上限、與蟲巢的關係。

## 4. 不變條件與驗收

- **基準不變**：`legacy`、`loyalist`、`rebel` 的出生與行為不變，`node qa/enemy-data-identity.mjs` 與基準一致，不重錄。
- **測試**：
  - 毒液命中不造成傷害而是中毒；醫療包能解毒。
  - 鉤舌要先蓄勢、會被打斷，拉扯遵守射程、視線與路線限制。
  - 感染詞條：死亡裂出小蟲受上限限制；攻擊帶毒。
  - 蟲潮的上限與不佔威脅額度。
  - 存讀檔保留所有新增狀態。
- **既有測試**：期望值原則上不改；非改不可時，在報告寫明理由。
- **報告**：寫進 `qa/results/`，並在本檔補「實作現況」一節。

## 5. 不用做（Claude 之後接）

- 毒液噴吐蟲、頭目的叫聲與台詞（蟲類沿用生物的叫聲分類）。
- 鉤舌預告線、毒液彈道、中毒狀態圖示等演出與介面。
- 所有數值調整：生命、傷害、射程、冷卻、中毒強度、蟲潮數量。

## 6. 實作現況（3.84.0，Codex，2026-09-14）

### 6.1 毒液與感染

- `src/swarm-tuning.js` 集中暫定數值：毒液命中增加3回合中毒，上限6；每個付費回合末沿用 `max(0,4-hazmat)` 傷害。持續時間相加，傷害不疊倍數、不隨樓層成長。既有環境地板優先於中毒結算、酸液重設3回合的規則維持，免費行動不結算。醫療包、終端治療與密封防護升級的解毒維持。
- `spitter`：HP34、射程6、裝甲0、1發、直接傷害0、XP1，非雜兵，照常掉資源、不掉武器。蟲族第3層起一份，第7層起多一份。命中按既有遠程命中／掩體／暗區／轉角規則，不打傷掩體；落空不施毒。
- **第一版只有玩家使用中毒狀態**；友軍、寵物、機體被毒液命中時不受傷且不中毒。感染者打中友軍仍有原本的直接傷害。理由是沿用已具醫療包／防護反制的玩家毒素系統，不在本批額外設計寵物與召喚物的治療經濟。這是刻意的攔截優勢，待實戰觀察。
- 新增 `infected` 標籤，給兩種感染士兵及共用的 fodder 卡；**效果還要求派系宣告**。`FACTIONS.swarm.infectedAffixes=['venomous','brood_host']` 固定給兩條隱藏詞條，從第一層起生效。未宣告的 legacy fodder 不取得詞條或改變行為；不更改原五條詞條的抽取池或亂數。其他派系日後可用同一個宣告與標籤。
- 帶毒 `venomous`：每發命中在原傷害外加中毒，施毒時顯現；多發感染士兵最多把時間加到6回合。育蟲 `brood_host`：死亡時顯現並裂出1–2隻幼蟲；包含被感染遊蕩者。使用獨立 `birthRandom(seed,floor,parentId,'infection-burst-v1')`，不抽戰鬥亂數。位置依上右下左，只選可通行、可跨越且沒有單位／物件／物品／危害的相鄰格；不夠則少放或不放。
- 幼蟲與蟲巢共用 `liveLimit=64`、`expendableLimit=6`，`expendable:true`、`reinforcement:true`；沒有經驗、廢料或物資，不帶感染詞條、不遞迴裂蟲。它們仍依既有雜兵規則給玩家追擊代幣。非雜兵感染者本身保持原來的獎勵與彈藥掉落。
- 感染士兵可以成為小菁英，保留兩條感染詞條且計入最低詞條數；非感染卡不能抽感染詞條。感染詞條出生時固定，不依深度另抽機率；之後可由派系資料調整是否提供。

### 6.2 鉤舌與反制

- 卡片 `tongue:true` 決定資格；兩個蟲族頭目已有，巨型蟲未加，之後改資料即可使用。只拉玩家；相鄰時使用原近戰，不用鉤舌。
- 射程5、曼哈頓距離，要求當下視線和可射擊的轉角射線。與狂戰士共用 `pullLanding(g,mover,anchor)`：四向鄰格為落點、依離被拉者距離與原順序取最近，掃過的直線不可穿牆、關門、隔板、實體物件或其他單位，斜線規則仍由既有 lineOfSight(move) 判定。沒有合法落點不蓄勢，繼續原AI。
- 第一次行動保存起點／玩家當時格／落點並預告；下一次行動才拉。玩家只要換格便使本次失敗，不轉向追蹤新格，也不改選其他落點。途中障礙、頭目位移、視線或射程失效均取消；即使玩家還在五格內，也可用換位閃避。
- 頭目死亡、失能、壓制到3層即取消，後者在施加壓制時就打斷，避免回合末衰減後遺漏。普通受傷不打斷；此例外不改狙擊／擲彈預告的原有壓制規則。
- 成功、失敗或打斷後冷卻4個付費回合，免費攻擊不扣冷卻。成功只拉、不立即攻擊；被拉玩家的等待加成、連續射擊與轉角暴露清除，按強制位移處理，不消耗額外玩家行動。玩家自身壓制／下錨不阻止外力拉扯，沒有額外贈送下錨解除。

### 6.3 保存與相容

- save **43**，profile5／backup1不變。新增的敵人欄位均可選：`tongueIntent:{origin:{x,y},target:{x,y},point:{x,y}}`、`tongueCooldown`、`broodReleased:true`、幼蟲的 `broodParent:parentId`。

- 遊戲生成世代不新增，這批是蟲族資料與執行期能力；legacy／loyalist／rebel的生成和既有亂數保持不變。正式 enemy-data 基準未重錄。

### 6.4 Claude 介面交接

- 毒液事件：`{type:'enemyShot',attackerType:'spitter',style:'venom',from,to,damage:0,miss?:true}`。`projectile:'venom'`、WEAPON_VISUALS.venom只是識別與單發描述，專用毒液畫法尚待接。玩家剩餘中毒回合讀 `player.poison`；真實模式按既有政策隱藏數字。
- 準備事件：`{type:'tongueTelegraph',sourceId,from:origin,to:target,landing,damage:0}`；持續狀態由 `tongueTelegraphs(g)` 查 `{kind:'tongue',sourceId,origin,target,landing,interruptible:true}`。UI 必須再按玩家可視性過濾；這個純規則查詢不自行過濾。取消會移除intent，線條需隨每一步快照更新。

- 名稱照舊用 `enemyDisplayName`／`revealedAffixes`，片段「帶毒」「育蟲」，未顯現只顯示問號；新增詞條台詞未接，沒有提前寫入隱藏效果。裂蟲沿用 `nestSpawn/burrow` 演出，畫面不顯示尚未發動的育蟲能力。
- `node qa/create-swarm-scenes.mjs` 產生四份 `qa/fixtures/swarm/*.json`：鉤舌蓄勢、毒液／中毒、感染士兵、自然蟲族第3層。請用 `?test=1` 匯入；別用正式存檔驗死亡。手機體感、台詞、毒液彈道／圖示、鉤舌線未由Codex驗收。
- 新素材在 `assets/pixel/swarm-v1/`；圖集第18格，前17格逐像素未動。完整prompt和製程在 `art/swarm-v1/README.md`。

## 7. 蟲潮提案（尚未實作，待演出合併與使用者確認）

- 建議第3層起，每層一個獨立的入侵點，戰鬥配置完成後以獨立雜湊挑非起點房的可達位置，不吃 allocateThreat 或改戰鬥敵人位置；玩家首次進入6格才啟動。
- 共4波、每波4隻、間隔3個付費回合；每波先以現有增援預告方式標格、倒數2回合再生出。總量16，存活專用上限12；滿額或格子受阻延後，不直接在玩家身上生成。
- 與蟲巢是兩套有限來源：巢穴保留原6隻額度與共用雜兵上限；蟲潮使用 `horde:true` 與獨立上限12，不佔 liveLimit／expendableLimit。實作時需統一修正這兩個容量查詢，避免其他增援因蟲潮被擠掉，並測試兩套來源共存。蟲潮幼體無經驗、廢料、物資且不可再裂蟲。
- 每層狀態存入新的可選 floor-owned `swarmWaves`，須加入 FLOOR_FIELDS／驗證：active、remaining、cooldown、serial、pending預告格／due。是否允許玩家破壞入侵點，留待下一批定案。
- 本批**沒有生成蟲潮，也沒有宣稱通過尚未實作的蟲潮上限測試**；現有感染裂蟲／蟲巢共用容量的測試已做。等Claude合併純移動演出再上線，避免目前逐隻播放讓回合過長。
